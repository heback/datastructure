# 기준값: 땅 칸마다 번호표를 붙이고, 맞닿은 칸끼리 작은 번호로 통일한다.
# 끝나면 서로 다른 번호의 개수가 섬의 개수이다.
def ref_islands(grid):
    # 딕셔너리 컴프리헨션: 땅 칸마다 처음엔 자기 좌표를 번호로 가진다

    cells = sorted(lab)  # 땅 칸 좌표를 정렬한 리스트
    changed = True  # 번호가 바뀌면 True로 두고 다시 훑는다
    while changed:
        changed = False
        for cell in cells + cells[::-1]:  # [::-1]은 뒤집은 리스트. 앞뒤로 훑는다

                nb = (cell[0] + dr, cell[1] + dc)
                if nb in lab and lab[nb] < lab[cell]:
                    lab[cell] = lab[nb]
                    changed = True
    # set은 중복을 없앤다. 서로 다른 번호의 수 = 섬의 수
    return len(set(lab.values()))

# (무한 반복으로 컴퓨터가 멈추는 일을 막는 장치이다)
def limited(real, limit, what):
    cnt = [0]  # 리스트에 담아야 안쪽 함수가 값을 바꿀 수 있다
    def wrapped(*a):  # *a: 인자를 몇 개든 그대로 받는다

        if cnt[0] > limit:
            raise RuntimeError(what + "를 너무 많이 불렀다(끝나지 않는 반복이 의심된다)")
        return real(*a)  # 원래 함수를 그대로 실행한다
    return wrapped

# 기준값 1: 모든 칸을 훑어 (r, c)와 상하좌우로 맞닿은 통과 가능 칸을 모은다.
# 집합 컴프리헨션이다. (행 차이 + 열 차이 = 1)이면 맞닿은 칸이다.
def ref_adj(grid, r, c, passable):
    return {(i, j) for i in range(len(grid)) for j in range(len(grid[0]))
            if abs(i - r) + abs(j - c) == 1 and grid[i][j] in passable}

# 기준값 2: 시작 칸에서 각 칸까지의 최소 거리를 구한다.
# 더 짧은 거리가 나오는 동안 되풀이해 훑는다.
def ref_dist(grid, start):
    d = {start: 0}  # 딕셔너리 {칸: 거리}. 시작 칸은 0
    changed = True  # 값이 바뀌면 True로 두고 다시 훑는다
    while changed:
        changed = False
        for cell in list(d):  # 훑는 중 d가 바뀌므로 복사해서 쓴다
            for n in ref_adj(grid, cell[0], cell[1], ".SE"):
                # 아직 모르는 칸은 아주 큰 값(10 ** 9)으로 본다
                if d[cell] + 1 < d.get(n, 10 ** 9):
                    d[n] = d[cell] + 1
                    changed = True
    return d

# 전이 연습 NUM(채점하지 않는다) · 시작 상태: 탐색마다 새 거리 딕셔너리와 큐를 만든다.
# 3에서 시작해 "+1" 또는 "x2"만 써서 14를 만드는 가장 적은 연산 횟수를 같은 틀로 찾는다. 수는 100 이하이다.
def next_states(n):                  # 제네레이터(제공). 상태 n에서 한 걸음에 갈 수 있는 수
    if n + 1 <= 100:  # 범위(100 이하) 안이면
        yield n + 1  # +1 한 수를 내준다
    if n * 2 <= 100:
        yield n * 2  # x2 한 수를 내준다

# NUM 점검: 기대 값은 적혀 있지 않다. 연산 횟수를 줄여 갈 수 있으면 계속 줄이는 다른 계산과 비교한다.
# globals(): 지금 정의된 이름 목록. num_bfs를 안 만들었으면 여기서 멈춘다.
assert "num_bfs" in globals(), "먼저 num_bfs(start, goal)를 작성한다(최소 연산 횟수를 돌려준다)"
# 기준값: 더 적은 횟수가 나오는 동안 되풀이해 start에서 각 수까지의 최소 연산 횟수를 구한다.
def ref_ops(start, goal):
    d = {start: 0}
    changed = True
    while changed:
        changed = False
        for n in list(d):
            for m in next_states(n):
                if d[n] + 1 < d.get(m, 10 ** 9):
                    d[m] = d[n] + 1
                    changed = True
    return d.get(goal, -1)  # 닿을 수 없으면 -1

AI 활용 3단계 · 이 과제에 맞춘 예허용 · 조건부 허용 · 금지

기준은 “AI에게 무엇을 시켰는가”이다. 개념·문법·오류 원인을 묻는 것은 허용이고, 과제 요구사항이나 완성된 구현 자체를 입력해 결과물(코드·글)을 받아 제출하는 것은 금지이다.

허용 — 성찰일지에 간단히 기록
  • “BFS와 DFS는 어떤 자료구조를 쓰는지 개념 설명해 줘”, “deque는 list와 뭐가 달라?” 같은 개념·문법 질의
  • “NameError: name is not defined가 무슨 뜻이야?”, “IndexError: string index out of range가 왜 나오는지 해설” 같은 오류 메시지 해설
  • “격자 탐색에서 4방향 이동은 보통 어떻게 표현해?” 같은 용어·설계 배경 설명(코드는 받지 않음)
  • 내 코드 결과가 점검 테스트와 다를 때 원인 힌트만 요청
조건부 허용 — 출처와 반영 여부를 성찰일지에 반드시 기록
  • 완성한 구현의 엣지 케이스 브레인스토밍(시작=도착, 도달 불가, 한 칸짜리 격자, 모두 바다/모두 땅, 빈 격자)
  • 내가 쓴 코드의 부작용과 반복 사용 시 동작을 검토해 달라는 요청(수정은 직접 한다)
  • 내 코드의 개선 아이디어 제안 요청(제안만 참고하고 코드는 직접 다시 작성)
  • 기록 예: “AI가 시작=도착 케이스를 제안 → 채택/미채택, 이유”
금지 — 적발 시 계획서의 위반 처리방안 적용
  • 과제 문장(“격자 미로의 S→E 최단 거리를 구하고 섬의 개수를 세는 함수를 작성하라”)을 그대로 입력해 전체 코드 생성
  • AI가 쓴 shortest_path_len/count_islands를 그대로, 또는 변수명만 바꿔 제출
  • 어느 목적에 BFS·DFS 중 무엇을 쓸지, 방문 기록을 어떻게 할지 등 설계 판단을 AI가 대신 내림
  • 성찰일지 AI 대필
수업 운영 규칙(금지 목록과 별개) 수업 중 A6~A10·A13~A14는 AI 도움 없이 수행한다. A14 형성평가는 AI를 쓰지 않는 시험 상황으로 운영하며, 위 위반 처리(감점 등)는 형성평가에 적용하지 않는다. 주간 과제를 제출할 때 위 3단계가 적용된다. A15에서 성찰일지에 AI 활용 내역을 쓰는 방법을 다시 안내한다.
