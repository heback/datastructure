A10 · 섬의 개수12분 · 개인

A7에서 만든 큐 틀로 격자의 이어진 땅을 한꺼번에 칠할 수 있다. 칠한 덩어리를 세어 섬의 개수를 구해 보자.

섬 하나 칠해 보기

땅(1)이 상하좌우로 이어진 덩어리를 섬이라 한다. 2행 3열 격자에서 왼쪽 위 땅 칸부터 이어진 땅을 모두 칠해 보자.

처음          (0, 0)에서 칠한 뒤

1 1 0         ● ● 0
0 0 1         0 0 1

칠하고 나서도 칠하지 않은 땅이 하나 남았다. 이 격자의 섬은 모두 몇 개일까?

(0, 0)과 (0, 1)이 한 섬이고 (1, 2)가 다른 섬이다. 칠하지 않은 땅이 남아 있으면 새 섬이 있다는 뜻이다.

ISLE를 손으로 세기

이제 6행 7열 격자 ISLE이다. 코드를 쓰기 전에 섬이 몇 개인지 손으로 세어 보자.

칠하는 코드 돌려 보기

손으로 한 칠하기를 큐로 하면 아래와 같다. [▶ 실행]하면 칠한 칸이 *로 나온다.

시작 칸 (0, 0)을 (1, 2)로 바꿔 다시 실행해 보자. 시작 칸은 3행 한 줄에 두 번 있다.

시작 칸을 (1, 2)로 바꾸면 *로 칠해지는 칸은?

(1, 2)는 이어진 땅이 없는 섬이다. 시작 칸이 속한 섬 하나만 칠해진다.

두 함수 완성하기

칠하기를 함수로 만든 것이 explore이고, 격자를 훑으며 섬을 세는 것이 count_islands이다. 빈칸은 세 개이다. ____17____(explore에서 큐의 맨 앞을 꺼내는 줄)부터 채우고, ____16____, ____15____ 순으로 채운다.

빈칸이 남아 있으면 NameError: name '____15____' is not defined가 나온다. 그 번호의 자리를 아직 안 채웠다는 뜻이다. seen은 칠한 칸을 모은 집합이고 (행, 열) 쌍이 들어 있다.

채운 뒤 나온 개수는 활동지 표의 2줄 ‘실제’ 칸에 쓴다.

점검 결과 읽기

통과하지 못한 번호와 원인은 활동지 3부 A13의 (가)에 쓴다.

과제 요건 네 가지
  • grid_neighbors는 yield를 쓰는 제네레이터여야 한다(리스트 반환 불가).
  • shortest_path_len의 제출본은 큐를 쓰는 너비 우선 탐색이어야 한다. 검증용 비교 코드를 직접 쓰는 것은 허용된다.
  • 입력 격자를 바꾸지 않고, 같은 입력으로 두 번 불러도 같은 값이어야 한다(seen=set() 같은 기본 인자를 쓰지 않는다).
  • 1×1500 같은 큰 입력에서도 RecursionError 없이 끝나야 한다.

상태를 두 수로 적기

3L짜리 통 하나와 5L짜리 통 하나가 있다. 물의 양을 (a, b)로 적는다. a는 3L 통, b는 5L 통의 물이다. 처음은 둘 다 빈 (0, 0)이고, 한 번 움직여 (3, 0)이나 (0, 5)로 갈 수 있다(통 하나를 가득 채운다).

(0, 5)에서 5L 통의 물을 3L 통에 붓는다. 3L 통이 가득 찰 때까지 붓는다면 상태는?

3L를 옮기면 5L 통에 2L가 남는다. 이렇게 한 번 움직여 갈 수 있는 상태가 이웃 상태이다.

이제 활동지 3부 A13의 (나) 카드에 상태, 이웃 상태의 예, 시작과 목표, BFS와 DFS 중 고를 것을 코드 없이 쓴다.

(선택 · 집에서) 숫자 변환 퍼즐

3에서 시작해 “+1” 또는 “×2”만 써서 14를 만드는 가장 적은 연산 횟수를 구한다. 이웃은 next_states가 내준다. 채점하지 않는다.

AI 활용 3단계 · 이 과제에 맞춘 예허용 · 조건부 허용 · 금지

기준은 “AI에게 무엇을 시켰는가”이다. 개념·문법·오류 원인을 묻는 것은 허용이다. 과제 요구사항이나 완성된 구현을 입력해 결과물(코드·글)을 받아 제출하는 것은 금지이다.

허용
  • “BFS와 DFS는 어떤 자료구조를 쓰는지 설명해 줘”, “deque는 list와 뭐가 달라?” 같은 개념·문법 질의
  • “NameError가 무슨 뜻이야?”, “IndexError가 왜 나오는지 해설해 줘” 같은 오류 메시지 해설
  • “격자 탐색에서 4방향 이동은 보통 어떻게 표현해?” 같은 용어·설계 배경 설명(코드는 받지 않음)
  • 내 코드 결과가 점검과 다를 때 원인 힌트만 요청
  • 용어 번역·개념 요약, 수업 자료 복습 질문
조건부 허용
  • 완성한 구현의 엣지 케이스 브레인스토밍(시작=도착, 도달 불가, 한 칸짜리 격자, 모두 바다/모두 땅, 빈 격자)
  • 내 코드의 부작용과 반복 사용 시 동작 검토 요청(수정은 직접 한다)
  • 내 구현의 시간·공간 복잡도 검토 요청. 복잡도는 내가 먼저 쓴 뒤 검토만 받는다
  • 개선 아이디어 제안 요청(제안만 참고하고 코드는 직접 다시 작성)
금지 — 적발 시 계획서의 위반 처리방안 적용
  • 과제 문장(“격자 미로의 S→E 최단 거리를 구하고 섬의 개수를 세는 함수를 작성하라”)을 그대로 입력해 전체 코드 생성
  • AI가 쓴 shortest_path_len/count_islands를 그대로, 또는 변수명만 바꿔 제출
  • BFS·DFS 중 무엇을 쓸지, 방문 기록을 어떻게 할지 등 설계 판단을 AI가 대신 내림
  • 복잡도 분석이나 구현 계획을 AI에게 대신 세우게 하여 제출
수업 운영 규칙 수업 중 A6~A10·A13~A14는 AI 도움 없이 수행한다. A14 형성평가는 AI를 쓰지 않는 시험 상황이며 위 위반 처리(감점 등)는 적용하지 않는다. 주간 과제를 제출할 때 위 3단계가 적용된다.
AI 도우미(화면 오른쪽 아래) 위 ‘허용’ 범위인 개념·문법 설명, 오류 원인, 힌트만 해 주고 과제 코드와 활동지 답은 알려 주지 않는다. 학교 계정으로 로그인해야 하며, 질문과 답은 교사가 볼 수 있게 기록된다. AI 도움 없이 하는 활동에서는 교사가 꺼 두므로 쓰지 않는다.
