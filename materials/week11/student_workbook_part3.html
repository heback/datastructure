A11 · 일반화 초안 카드3차시 · 4분 · 개인

산출물: 일반화 초안 카드 (개인 메모)

학습 내용 · 일반화 문장 쓰는 법과 네 주제
  • 일반화 문장은 사례 하나의 결과가 아니라 여러 사례에 통하는 말이다. “개념 + 개념 + 관계”로 쓴다. 사례 이름(G1, H, MAZE, ISLE)은 개념어(그래프, 격자, 노드, 컨테이너 등)로 바꾼다.
  • 형태 예(8주차 소재): “값 5를 찾을 때 3번 비교했다”(사례) → “정렬 규칙을 지키는 이진 트리에서는 비교 한 번마다 찾을 범위가 한쪽 가지로 줄어든다”(일반화).
  • 네 주제와 다시 볼 활동: 탐색 틀과 꺼내는 규칙(A2·A3·A10), 최단 거리(A4·A7·A9), 연결 요소(A10), 구현 선택(A8 T1~T3).
  • 점검: 내 문장에서 “미로”나 사례 이름을 지워도 말이 되는지 보고, 소문·섬·물통 퍼즐에 대어 보아 통하지 않는 사례가 있으면 반례 칸에 쓴다.

A1~A10에서 발견한 것을 “개념 + 개념 + 관계” 형태의 문장 한 개로 쓴다. 아래 네 주제 중 오늘 내 생각이 가장 크게 바뀐 하나를 골라 쓴다.

활동을 마친 뒤 열어 확인한다 · 정제된 일반화 문장 G1~G4와 구별 기준표

이 G1~G4는 일반화 문장의 번호이며 그래프 G1과 번호만 같다.

  • G1 상태 공간 탐색은 “지금 상태에서 한 걸음에 갈 수 있는 이웃 상태를 꺼내 보고, 이미 본 상태는 visited로 걸러내는” 하나의 틀이며, 이 틀에서 다음에 꺼낼 상태를 가장 최근 것(스택·Call Stack)으로 고르면 한 갈래를 끝까지 파고드는 DFS가, 가장 오래된 것(큐)으로 고르면 가까운 것부터 넓히는 BFS가 되어 방문 순서와 처음 도착하는 길이 달라진다. (근거: A1, A2, A3, A6, A13)
  • G2 큐는 시작에서 걸음 수가 같은 노드를 모두 처리한 뒤에야 한 걸음 더 먼 노드를 처리하므로 처음 도착한 경로의 간선 수가 최소임이 보장되지만, 스택·Call Stack은 한 갈래를 먼저 끝까지 가므로 처음 도착한 경로가 최단이라는 보장이 없고 이웃을 보는 순서에 따라 길이가 달라진다. 따라서 최단 거리가 목적이면 BFS를 구별해 쓴다. (근거: A4, A7, A9)
  • G3 연결된 구역을 모두 묶어 세는 목적(연결 요소 추적, 섬의 개수)은 방문 순서가 결과를 바꾸지 않으므로 DFS와 BFS가 같은 답을 내며, 이때의 선택은 입력 크기에 따른 구현 비용(재귀 깊이, 큐 연산 비용)과 안전성에 달려 있고 visited가 없거나 표시 시점이 어긋나면 중복·무한 반복이 생긴다. (근거: A8 T1, A10, A13)
  • G4 재귀(Call Stack)로 쓴 DFS는 간결하지만 깊이가 호출 한계에 묶여 입력이 커지면 실패하고, 이를 명시적 스택으로 바꾸면 한계가 없어지는 대신 이웃 처리 순서·visited 표시를 직접 챙겨야 하며, 큐도 맨 앞을 꺼내는 비용이 작은 자료구조(deque)를 골라야 탐색이 입력 크기에 비례해 끝난다. (근거: A3, A8 T2·T3, A10)
  • 구별 기준표: 걸음 수가 가장 적은 길 → BFS(큐가 가까운 것부터 처리해 처음 도착한 길의 간선 수가 최소). 연결된 구역의 개수 → 둘 다 가능(방문 순서가 개수를 바꾸지 않으므로 구현 비용·안전성으로 고른다). 어떤 길로든 이어져 있는지만 → 둘 다 가능(길이는 묻지 않는다).
  • visited를 끄면: G1의 A-B-D-C-A처럼 한 바퀴 돌아 되돌아오는 길(사이클)이 있는 그래프에서 같은 노드를 계속 다시 처리해 끝나지 않는다.
  • (선택) 토론 질문: D1 “어떤 순서로 탐색하는 것이 정답일까?” 정답은 하나인가, 목적에 따라 다른가? “DFS로 길을 찾았으니 충분하다”는 언제 틀리는가? D2 섬의 개수에서 대각선으로 맞닿은 땅도 같은 섬인가? 문제의 정의가 알고리즘 선택이 아니라 이웃 규칙을 바꾸는가? D3 재귀 DFS는 코드가 가장 짧은데 입력이 커지면 실패한다. 짧고 읽기 쉬운 코드와 안전한 코드 중 무엇을 택할 것인가? sys.setrecursionlimit을 올리면 해결되는가?

학습 내용 · 새 문제를 상태와 이웃으로 바꾸는 법
  • 상태는 문제의 한 순간을 나타내는 값(묶음)이다. 이웃 상태는 허용된 동작을 한 번 했을 때 바뀌는 상태이다. 이 둘을 정하면 노드 = 상태, 간선 = 동작 한 번으로 보고 미로·섬과 같은 탐색 틀을 쓸 수 있다.
  • 작은 예(NUM): 상태 = 수 n(1~100), 이웃 = n+1과 n×2(100 이하일 때), 시작 = 3, 목표 = 14. 그래프를 미리 만들어 두지 않고 next_states(n)이 이웃을 필요할 때 계산해 내준다. 3의 이웃은 4와 6, 4의 이웃은 5와 8, 6의 이웃은 7과 12이다.
  • 물통 퍼즐 카드에는 (1) 상태를 이루는 값 (2) 동작 한 번으로 바뀌는 이웃 상태의 예 (3) 시작과 목표 (4) 최소 단계를 구하려면 BFS와 DFS 중 무엇이어야 하는지와 그 까닭을 쓴다. 코드는 쓰지 않는다.
  • (가) 점검은 실습 코드 3부 A13 블록의 점검 코드를 실행해 FAIL 줄 앞의 항목 번호를 보고, 통과하지 못한 번호와 원인을 쓴다. 항목이 무엇을 보는지는 그 블록의 안내에 있다.

(나) 전이: 새 문제의 상태 공간 정의하기 (채점하지 않는다)

물통 퍼즐: 3L 통과 5L 통이 있고 둘 다 비어 있다. 물을 가득 채우기, 비우기, 다른 통으로 옮기기만 할 수 있다. 한 통에 정확히 4L를 만들 수 있는가? 코드를 쓰지 말고 다음 네 가지를 쓴다. (1) 상태 하나를 무엇으로 나타내는가 (2) 한 걸음에 갈 수 있는 이웃 상태의 예 (3) 시작과 목표 (4) BFS와 DFS 중 최소 단계를 구하려면 무엇이어야 하는가와 그 까닭

활동을 마친 뒤 열어 확인한다 · 물통 퍼즐 상태 정의와 NUM 확인(채점 외)
  • 물통 퍼즐: 상태 = (3L 통의 물, 5L 통의 물) = (a, b). 이웃 상태는 가득 채우기 (3, b)·(a, 5), 비우기 (0, b)·(a, 0), 한 통이 비거나 다른 통이 찰 때까지 붓기(예: (3, 0)에서 (0, 3))로 만든다. 시작은 (0, 0), 목표는 어느 한 통이 4L인 상태이다. 최소 단계를 구하려면 걸음 수가 같은 상태를 모두 본 뒤 한 걸음 더 먼 상태를 보는 BFS(큐)여야 한다. 4L를 만들 수 있고, 최소 6단계이다: (0,0) → (0,5) → (3,2) → (0,2) → (2,0) → (2,5) → (3,4).
  • NUM(채점 외): 3에서 14까지 최소 3회, 경로 3 → 6 → 7 → 14. 14를 꺼낼 때까지 꺼낸 상태 11개, 발견한 상태 18개이다. 거리별 상태: 거리 0 {3}, 1 {4, 6}, 2 {5, 8, 7, 12}, 3 {10, 9, 16, 14, 13, 24}. 노드는 수, 간선은 “+1”과 “×2”이고 메모리에 그래프는 없다. 같은 수(6은 3×2로도, 3→4→5→6으로도)를 여러 경로로 만난다. 같은 이웃 순서(+1 먼저)의 재귀 DFS가 처음 찾은 연산 횟수는 11이다.
  • 코드를 고치지 않고 새 입력에서도 통과해야 과제 점검을 통과한 것이다. 이 점은 12주차·13주차에서도 이어진다(같은 상태를 다시 계산하지 않기).
