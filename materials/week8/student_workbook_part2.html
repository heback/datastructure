None으로 기본값 만들기

기본값을 None으로 두고, 함수 안에서 None인지 보아 새로 만드는 방법이 있다. 아래 함수는 name이 None일 때만 “친구”를 만든다.

def hello(name=None):
    if name is None:
        name = "친구"
    print(name, "안녕")

hello()
hello("지아")

hello("지아")를 실행하면 무엇이 출력될까?

name이 None이 아니므로 if를 지나가고, “지아 안녕”이 나온다.

기본값 들여다보기

함수이름.__defaults__는 파이썬이 함수에 저장해 둔 기본 인자 값들을 튜플로 보여 준다. 예를 들어 def f(a, b=5)이면 f.__defaults__는 (5,)이다.

def g(x, y=3, z=4)의 g.__defaults__는?

y와 z의 기본값 3, 4가 담겨 (3, 4)이다.

실습 코드 A12의 관찰 칸을 실행해 호출 전과 후의 출력을 괄호까지 그대로 옮긴다.

관찰 코드출력
함수를 한 번도 호출하기 전 collect_inorder.__defaults__
한 번 호출한 뒤 collect_inorder.__defaults__

출력의 달라진 점을 근거로, 기본값 식은 언제 평가되는지 한 문장으로 쓴다.

여기까지 원인을 관찰하고 고친 뒤 다른 방법과 견주었다. A13에서는 오늘 발견한 것을 일반화 문장으로 다듬는다.

활동을 마친 뒤 열어 확인한다 · 원인, 수정, 대안
  • 원인: 기본값 []은 def가 실행되어 함수가 만들어질 때 한 번만 만들어져 함수에 저장되고, 모든 호출이 같은 리스트를 공유한다. __defaults__가 ([],)에서 호출 뒤 값이 든 리스트로 바뀐 것이 증거이다. 한 번의 순회 안에서는 재귀 호출이 visited를 명시적으로 넘겨 정상으로 보이다가, 인자 없이 부르는 두 번째 호출에서 드러난다.
def collect_inorder(node, visited=None):
    if visited is None:      # 인자를 주지 않았을 때만 새 리스트를 만든다
        visited = []
    if node is None:         # (나머지 줄은 그대로)
        return visited
방법좋은 점대가
None 센티널호출이 간단하다함수 안에 None 검사 두 줄이 필요하다
결과 리스트를 인자로 받기(A6 방식)기본값이 없어 안전하다호출하는 쪽이 매번 []를 만들어 넘겨야 한다
내부 헬퍼 함수 / 제너레이터호출이 간단하고 안전하다함수 안에 함수가 하나 더 생기거나 list()로 감싸야 한다
  • 잘못된 수정 두 가지: 호출할 때마다 []를 직접 넘기면 그 호출은 맞지만 인자 없이 부르면 다시 누적된다. 함수 안에서 무조건 visited = []를 쓰면 재귀 호출마다 새 리스트가 생겨 결과가 사라진다.
  • 어느 방법이 낫다는 정답은 없고, 치르는 대가를 말할 수 있으면 된다.

내가 가졌던 오해가 오늘 어느 활동에서 확인되었는지 찾아 보자. 닫힌 상자는 표를 채운 뒤에 연다.

세 진술 판단하기

진술이 참인지 거짓인지 고르고, 근거가 된 활동 번호를 쓴다(꼴: A1, A5). 근거가 된 활동이 없으면 “없음”이라고 쓴다.

진술참/거짓근거가 된 장면(활동 번호)
① 부모보다 왼쪽 자식이 작고 오른쪽 자식이 크면 BST이다.
② BST에서 탐색은 항상 O(log N)이다.
③ 함수의 기본값 []는 호출할 때마다 새로 만들어진다.

생각이 바뀐 것

(선택) 세 진술 중 오늘 처음 생각을 바꾼 것은 몇 번이며, 바꾸게 한 활동은 무엇인가? 꼴은 “○번, A○”이다. 바꾼 것이 없으면 비워 둔다.

활동을 마친 뒤 열어 확인한다 · 오개념 점검 진술의 답
  • ① 거짓: 부모와의 비교만 맞아도 BST가 아닐 수 있다(A7의 10 아래 5, 5의 오른쪽 12). 모든 부분 트리에서 성립해야 한다.
  • ② 거짓: 균형일 때만 O(log N)이고 T5처럼 쏠리면 O(N)이다(A9).
  • ③ 거짓: 기본값 []은 함수가 정의될 때 한 번만 만들어져 모든 호출이 공유한다(A11·A12).
  • 세 진술 모두 ‘원래 알고 있었다’고 느꼈다면 ①의 반례를 직접 말해 볼 수 있는지 점검한다.

이 정리는 마지막 활동을 마친 뒤 연다. 활동 중에 미리 열지 않는다.

활동을 마친 뒤 확인 · 정리

오늘의 일반화 A10·A13에서 쓴 내 문장과 이 정리를 비교한다.

  • 계층 구조는 부모–자식 관계가 재귀적으로 반복되므로, 한 노드에 쓴 처리 규칙이 모든 부분 트리에 똑같이 적용된다.
  • 같은 구조라도 노드를 처리하는 시점(전·중·후)에 따라 결과 순서가 달라지며, 데이터에 불변식이 있으면 특정 시점의 순회가 그 불변식을 결과로 드러낸다(BST의 중위 순회는 정렬 순서이다).
  • 정렬 불변식을 유지하는 구조는 매 비교마다 탐색 범위를 줄이지만, 입력 순서에 따라 균형이 깨지면 그 이점이 사라진다.
  • 재귀 호출들이 하나의 상태를 함께 쓸 때, 그 상태가 어디서 만들어지고 누구에게 속하는지(스코프·수명)가 결과를 결정한다. 함수 정의 시점에 한 번 만들어지는 기본값은 모든 호출이 공유한다.

BST의 배치 규칙 모든 노드에서 왼쪽 부분 트리의 값은 그 노드보다 작고, 오른쪽 부분 트리의 값은 그 노드보다 크거나 같다. 부모와의 비교만이 아니라 모든 조상과의 관계가 성립해야 한다.

복잡도 결론

  • 순회: 노드가 N개이면 모든 노드를 한 번씩 방문하므로 O(N)이다(빈 자리 호출까지 세면 호출은 2N+1번이다).
  • BST 탐색·삽입: 비교 횟수가 높이 h에 비례하여 O(h)이다. 균형이 잡히면 h가 약 log₂N이라 O(log N)이고, 값이 정렬된 순서로 들어와 한쪽으로 치우치면 h가 N이라 O(N)이다.

흔한 오개념

  • “BST는 부모보다 왼쪽 자식이 작고 오른쪽 자식이 크면 된다” → 서브트리 전체의 값이 기준을 지켜야 한다.
  • “중위 순회는 항상 정렬된 결과를 준다” → BST에서만 그렇다. 일반 트리의 중위 순회는 정렬과 무관하다.
  • “BST는 언제나 O(log N)이다” → 입력 순서에 따라 한쪽으로 치우치면 O(N)이다.
  • “기본 인자에 []를 쓰면 호출마다 새 리스트가 생긴다” → 기본값은 함수를 정의할 때 한 번만 만들어져 모든 호출이 같은 리스트를 공유한다. 그래서 None으로 두고 함수 안에서 새로 만든다.
