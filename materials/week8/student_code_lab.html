사용법#how

  1. 코드는 이 페이지의 코드 편집기에서 쓰고 [▶ 실행]으로 브라우저에서 바로 확인한다(.py 파일을 따로 만들지 않는다). 편집기 위의 [예시 코드]를 눌러 필요한 코드의 [편집기에 추가]를 누르면 편집기의 맨 아래에 그 코드가 이어 붙는다.
  2. 같은 페이지의 편집기들은 파이썬 환경을 함께 쓴다. 앞 편집기에서 실행한 함수와 변수는 뒤 편집기에서 그대로 쓸 수 있으므로 다시 붙이지 않아도 된다. 새로고침하거나 [실행 환경 초기화]를 누르면 환경이 비어, 아직 정의하지 않은 이름을 쓰면 NameError가 난다. 이는 그 이름을 정의한 코드를 아직 실행하지 않았다는 뜻이므로 정의한 편집기를 먼저 실행한다.
  3. 다른 쪽(페이지)의 코드가 필요하면 먼저 그 쪽 편집기에서 실행해 성공시킨 뒤, 이 쪽 편집기의 [앞 쪽 코드 불러오기] 단추를 누른다. 한 번 실행이 15초를 넘기면 멈추고 환경이 초기화된다. 무한 반복이나 기저 조건 누락이 없는지 확인한다.
  4. 테스트가 실패하면 AssertionError 또는 NotImplementedError가 나온다. 이는 아직 채울 곳이 남아 있다는 뜻이다. 편집기의 내용은 [저장(JSON)]으로 저장되어 제출된다.
  5. 노드는 Node(val, left, right), 필드는 val, left, right로 통일한다.
  6. 이 파일은 2차시(A6~A9)에 사용한다.

A6 · 세 순회를 재귀 함수로 구현하기16분 · 개인

전위(preorder)는 완성되어 있다. 이를 읽고 중위·후위를 직접 작성한다. 결과는 out 리스트에 모으며, 호출하는 쪽이 새 리스트를 넘긴다(preorder(t, [])).

순서 ① 아래 편집기의 [예시 코드]를 열어 [제공 코드] 공통 코드와 [뼈대]를 한 번씩만 [편집기에 추가]한다. ② 편집기에서 inorder와 postorder의 TODO를 직접 쓴다. ③ [테스트]를 [편집기에 추가]하고 [▶ 실행]한다. 뼈대를 다시 추가하면 내가 쓴 함수 아래에 처음 상태의 함수가 이어 붙어 내 함수를 덮어쓰므로 처음 한 번만 넣는다.

  • 이미 완성된 전위 코드에서 추가하는 줄이 어디인지 먼저 찾고, 활동지 A3·A4에서 정리한 처리 시점을 근거로 중위·후위에서 그 줄이 있을 자리를 정한다. 막히면 활동지 A3 추적표에서 그 순회를 한 줄씩 따라가며 어느 때 출력했는지 확인한다.
  • out은 결과를 모으는 리스트이며 호출하는 쪽이 새 빈 리스트를 넘긴다: preorder(t1, []). 한 번의 호출 안에서 모든 재귀 호출이 같은 out에 이어 붙인다.
  • 테스트 읽는 법: PASS는 통과, FAIL은 기대와 다른 결과, ‘오류’로 시작하는 줄은 함수가 오류로 멈춘 것이다. 같은 함수를 두 번 호출해도 같은 결과가 나오는지도 본다. return out을 빼먹으면 결과가 None이 되어 FAIL이 나온다. 끝에 “모든 테스트 통과”가 출력되면 이 활동이 끝난다.

공통 코드 (Node, insert, build)

class Node:  # 트리의 노드를 만드는 설계도(클래스)이다
    def __init__(self, val, left=None, right=None):  # 노드를 만들 때 자동 실행된다
        self.val = val  # 노드에 저장할 값
        self.left = left  # 왼쪽 자식(없으면 None)
        self.right = right  # 오른쪽 자식(없으면 None)

# insert는 A7(손으로 삽입)을 마친 뒤에 읽는다. A6에서는 Node와 build만 쓴다.
def insert(root, val):          # BST 삽입 (A7)
    if root is None:  # 빈 자리(None)인가?
        return Node(val)  # 그 자리에 새 노드를 만든다
    if val < root.val:
        root.left = insert(root.left, val)
    else:
        root.right = insert(root.right, val)
    return root  # 갱신한 트리의 루트를 돌려준다

def build(values):              # 값 목록을 차례로 삽입해 BST를 만든다
    root = None  # 빈 트리에서 시작한다
    for v in values:  # 값을 앞에서부터 하나씩 꺼낸다
        root = insert(root, v)  # v를 삽입하고 루트를 갱신한다
    return root  # 완성된 트리의 루트를 돌려준다

t1 = Node("A", Node("B", Node("D"), Node("E")), Node("C", None, Node("F")))

# (이름, 트리, 전위 기대, 중위 기대, 후위 기대)를 묶은 목록이다.
CASES = [
    # list("ABC")는 글자를 담은 리스트 ["A", "B", "C"]이다.
    ("T1", t1, list("ABDECF"), list("DBEACF"), list("DEBFCA")),
]
# (이름, 함수) 쌍이다. 함수도 변수처럼 담아 둘 수 있다.
FUNCS = (("preorder", preorder), ("inorder", inorder), ("postorder", postorder))

# 함수를 새 빈 리스트와 함께 실행한다. 오류가 나면 오류 이름을 돌려준다.
def run(fn, tree):
    try:
        return fn(tree, [])
    except Exception as e:  # 오류가 나도 테스트가 멈추지 않게 받는다
        print("오류", type(e).__name__, e)  # 오류 이름과 메시지를 보여 준다
        return type(e).__name__

failures = []  # 틀린 항목을 모아 둔다
for name, tree, *wants in CASES:  # *wants: 나머지 기대 결과 3개
    for (label, fn), want in zip(FUNCS, wants):  # 함수와 기대 결과를 짝지어 본다
        got = run(fn, tree)  # 실제 결과
        ok = (got == want) and (run(fn, tree) == want)   # 같은 호출을 한 번 더 해서 비교한다
        print("PASS" if ok else "FAIL", name, label)  # 통과 여부 출력
        if not ok:
            failures.append((name, label))  # 틀린 항목으로 기록한다
for label, fn in FUNCS:
    if run(fn, None) != []:  # 빈 트리(None)는 []가 나와야 한다
        print("FAIL 빈 트리", label)
        failures.append(("빈 트리", label))

# 틀린 항목이 하나라도 있으면 AssertionError가 난다.
# 위의 FAIL 줄에서 어느 함수가 틀렸는지 찾는다.
assert not failures, "실패 %d건: %s" % (len(failures), failures)
print("모든 테스트 통과")

A9 · T4와 T5의 방문 횟수 확인하기11분 · 모둠

먼저 손으로 두 트리를 그리고 값 7을 찾을 때의 방문 수를 센다. 손으로 센 뒤에 아래 코드로 확인한다. 이 코드는 확인용이니 [▶ 실행]만 한다. 값을 바꾸어 보고 싶으면 실행 칸에서 바꾸어 보아도 된다(저장되지 않는다). 실행 칸에는 [예시 코드]의 세 블록을 위에서 아래 순서대로 [편집기에 추가]한다.

공통 코드 (Node, insert, build)

class Node:  # 트리의 노드를 만드는 설계도(클래스)이다
    def __init__(self, val, left=None, right=None):  # 노드를 만들 때 자동 실행된다
        self.val = val  # 노드에 저장할 값
        self.left = left  # 왼쪽 자식(없으면 None)
        self.right = right  # 오른쪽 자식(없으면 None)

def insert(root, val):          # BST 삽입 (A7)
    if root is None:  # 빈 자리(None)인가?
        return Node(val)  # 그 자리에 새 노드를 만든다
    if val < root.val:
        root.left = insert(root.left, val)
    else:
        root.right = insert(root.right, val)
    return root  # 갱신한 트리의 루트를 돌려준다

def build(values):              # 값 목록을 차례로 삽입해 BST를 만든다
    root = None  # 빈 트리에서 시작한다
    for v in values:  # 값을 앞에서부터 하나씩 꺼낸다
        root = insert(root, v)  # v를 삽입하고 루트를 갱신한다
    return root  # 완성된 트리의 루트를 돌려준다
학습 내용 · steps_to_find 읽는 법
  • 이 함수는 루트에서 출발해 찾는 값이 나올 때까지 내려가며 방문한 노드 수(steps)를 센다. 한 노드를 지날 때마다 1을 더하고, 찾는 값과 같으면 바로 그 수를 돌려준다.
  • 찾는 값이 노드의 값보다 작으면 왼쪽으로, 아니면 오른쪽으로 내려간다. A7의 삽입 규칙과 같은 방향 결정이다. 빈 자리(None)에 닿으면 반복이 끝나고 센 수를 돌려준다.
  • 활동지 A9의 ‘방문(비교)한 노드 수’는 이 값과 같은 기준으로 센 것이다.

방문 수 세기 (steps_to_find)

def steps_to_find(root, target):
    """target을 찾을 때까지 방문(비교)한 노드 수를 센다."""
    steps = 0  # 방문한 노드 수
    node = root  # 루트에서 출발한다
    while node is not None:  # 빈 자리에 닿을 때까지 반복한다
        steps += 1  # 노드를 하나 방문했다고 센다
        if target == node.val:  # 찾는 값이면
            return steps  # 지금까지 센 수를 돌려준다
        node = node.left if target < node.val else node.right  # 작으면 왼쪽, 아니면 오른쪽
    return steps  # 못 찾고 끝나도 센 수를 돌려준다

  • 서술은 “시간은 O(...)이다. 왜냐하면 ...”처럼 값과 근거를 함께 쓴다. O(N)은 입력 크기 N이 커질 때 걸리는 일의 양이 N에 비례해 늘어나는 정도를 나타내며, 상수배는 무시한다.
  • 시간의 근거는 활동지 A3에서 센 전체 호출 횟수와, 호출 한 번이 하는 일의 크기이다.
  • 공간의 근거는 활동지 A9에서 센 ‘호출이 가장 깊이 쌓인 순간의 개수’(호출 스택)와 결과 리스트의 크기이다. 둘을 구분해서 쓰고, 트리가 균형일 때와 한쪽으로 쏠렸을 때를 나누어 생각한다.

과제 서술 입력

AI 활용 3단계 · 이 과제에 맞춘 예허용 · 조건부 허용 · 금지

기준은 “AI에게 무엇을 시켰는가”이다. 개념·문법·오류 원인을 묻는 것은 허용이고, 과제 요구사항이나 완성된 구현 자체를 입력해 결과물(코드·복잡도 분석·글)을 받아 제출하는 것은 금지이다.

허용 — 성찰일지에 간단히 기록
  • “전위·중위·후위 순회는 무엇이 다른가?” 같은 개념 질의
  • “IndentationError: unexpected indent의 원인이 뭐야?” 같은 오류 해설
  • 처음 보는 파이썬 용어나 문법이 무슨 뜻인지 묻는 개념 설명
  • 내가 쓴 순회 코드의 결과 순서가 틀릴 때, 원인에 대한 힌트만 요청(코드는 요청하지 않음)
조건부 허용 — 출처와 반영 여부를 성찰일지에 반드시 기록
  • 내가 완성한 순회 구현과 내가 쓴 복잡도 분석이 맞는지 검토 요청(분석은 먼저 내가 직접 쓴다)
  • 내 코드의 엣지 케이스(빈 트리, 자식 하나뿐인 노드, 편향 트리) 브레인스토밍
  • 내가 쓴 코드의 개선 아이디어 제안 요청(제안만 참고하고 코드는 직접 다시 작성)
  • 기록 예: “AI가 빈 트리 테스트를 제안 → 채택, 이유: 기저 조건 확인에 필요”
금지 — 적발 시 계획서의 위반 처리방안 적용
  • “전/중/후위 순회 재귀 함수를 구현하라”는 과제 문장을 그대로 입력해 전체 코드 생성
  • AI가 쓴 순회 코드를 그대로, 또는 변수명만 바꿔 제출
  • 복잡도 분석, 구현 계획(재귀 구조, 결과 누적 방식 선택)을 AI가 대신 세움
  • 성찰일지 AI 대필
수업 운영 규칙(금지 목록과 별개) 수업 중 A6·A14·A15는 AI 도움 없이 수행한다. A15 형성평가는 AI를 쓰지 않는 시험 상황으로 운영하며, 위 위반 처리(감점 등)는 형성평가에 적용하지 않는다. 주간 과제를 제출할 때 위 3단계가 적용된다. A16에서 성찰일지에 AI 활용 내역을 쓰는 방법을 다시 안내한다.
