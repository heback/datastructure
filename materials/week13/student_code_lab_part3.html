13주차 실습 코드 3부 — 예측하고 실행하는 함정 코드 T1~T4

A10 시작 때(A9 완료 후) 쓴다. 그럴듯해 보이는 코드가 어디서 어긋나는지 실행해서 직접 확인한다.

학번·이름은 위쪽 저장 바에 쓴다.

#사용법#A10목록

사용법#how

  • 편집기에 코드가 미리 들어 있다. 읽고 결과를 먼저 예측한 뒤 [▶ 실행]을 누른다.
  • 고친 코드는 같은 편집기에 쓰고 다시 실행한다. [처음 코드로]는 편집기를 처음 상태로 되돌린다.
  • 편집기에 쓴 내용은 자동으로 보관된다. 다 했으면 위의 [저장(JSON)]으로 제출 파일을 만든다.
단축키와 오류가 날 때
  • Ctrl(⌘)+Enter는 실행, Tab은 들여쓰기, Shift+Tab은 내어쓰기이다.
  • 같은 쪽의 편집기는 파이썬 환경을 함께 쓴다. 쪽을 새로 열면 정의가 지워지므로 위의 편집기부터 다시 실행한다.
  • 오류가 나면 맨 아래 줄부터 읽는다. 오류 이름과 까닭이 거기에 있다.
  • 실행이 15초를 넘기면 멈추고 환경이 초기화된다.

A10 · 함정 코드를 예측하고 실행하기12분 · 개인(예측 → 실행 → 원인)

겉으로는 그럴듯한 코드 세 개(T1~T3)가 있다. 읽고 결과를 먼저 예측한 뒤, 실행해서 맞춰 보자.

T1 읽고 예측하기

피보나치 수를 재귀로 구하는 함수이다. 같은 계산을 다시 하지 않으려고 memo를 두었고, 호출될 때마다 calls를 센다.

fib_t1(20)을 부르면 호출 횟수는 어떨까?

고른 답을 숫자로 바꿔 한 줄로 써 두자. 틀려도 지우지 않는다.

예측

T1 실행하고 고치기

[▶ 실행]을 눌러 예측과 견주어 보자. 어긋난 곳이 보이면 원인이 되는 줄을 찾아 같은 편집기에서 고치고 다시 실행한다. 예측과 실제, 원인은 활동지 2부 A10의 T 칸에 적는다.

고친 코드에서 T1 n = 6 줄의 호출 횟수는 몇 번인가?

25번에서 11번으로 줄었다.

막힐 때 힌트

memo를 만드는 줄에 print를 하나 넣고 fib_t1(6)을 한 번 부른다. 그 줄이 몇 번 찍히는지 센다.

T2 읽고 예측하기

동전 coins로 amount를 만드는 최소 개수를 표 dp로 구한다. INF는 ‘만들 수 없음’을 뜻하는 아주 큰 값이다.

5원과 7원 동전으로 3원은 만들 수 없다. dp_t2([5, 7], 3)은 무엇을 돌려줄까?

두 호출의 결과를 한 줄로 써 두자.

예측

T2 실행하고 고치기

실행해서 예측과 견주고, 원인이 되는 줄을 고쳐 다시 실행한다. 표 dp의 처음 값이 무엇을 뜻하는지 생각하면 찾기 쉽다.

고친 뒤 T2 출력의 첫 번째 값은 얼마인가?

[1, 3, 4]로 6원은 3 + 3, 동전 2개이다. 두 번째 값은 만들 수 없는 경우의 출력이다.

T3 읽고 예측하기

R행 C열 표(2차원 리스트)를 만들고 맨 왼쪽 위 칸에만 1을 쓰는 함수이다.

make_grid_t3(3, 4)를 출력하면 1은 모두 몇 개일까?

어느 칸이 1이 될지 한 줄로 써 두자.

예측

T3 실행하고 고치기

실행해서 예측과 견주자. 어긋나면 dp의 행이 몇 개의 리스트로 이루어졌는지 따져 보고, 원인이 되는 줄을 고쳐 다시 실행한다.

고친 뒤 T3 출력에서 1이 들어 있는 줄은 몇 줄인가?

1이 들어 있는 줄은 맨 왼쪽 위 칸이 있는 첫 행뿐이다.

T4 재귀가 깊어지면

같은 값을 메모 재귀와 반복(표)으로 구한다. 재귀 한도는 코드에서 바꾸지 않는다. 이 칸의 내용은 저장되지 않는다.

fib_memo_t4(3000, {})은 끝까지 계산될까?

실행해서 확인해 보자. T4는 활동지에 적지 않는다.
