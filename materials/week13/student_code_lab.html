#사용법#A7목록

사용법#how

  1. 이 쪽의 ‘내 코드’ 칸은 코드 편집기이다. 코드를 쓰고 [▶ 실행](또는 Ctrl/⌘+Enter)을 누르면 이 쪽 안에서 바로 파이썬이 실행된다. 파이썬을 설치하거나 .py 파일을 만들 필요가 없다. 처음 한 번은 파이썬을 준비하느라 몇 초 걸린다.
  2. 편집기의 [예시 코드]를 누르면 같은 활동의 코드 블록이 나온다. [복사] 또는 [편집기에 추가]로 가져온다. [편집기에 추가]는 편집기의 맨 아래에 이어 붙인다. 뼈대(A7-2)는 제공 코드(A7-1)의 calls, steps, fib_naive를 쓰므로 제공 코드를 먼저 편집기에 추가한다.
  3. 같은 쪽의 편집기들은 파이썬 환경을 함께 쓴다. 앞 편집기에서 실행한 함수와 변수는 뒤 편집기에서 그대로 쓸 수 있다. 쪽을 새로 열거나 [실행 환경 초기화]를 누르면 정의가 지워지므로 위의 편집기부터 다시 실행한다. 다른 쪽에서 만든 함수가 필요하면 그 쪽의 편집기에서 실행을 성공시킨 뒤, 이 쪽의 [앞 쪽 코드 불러오기]를 누른다. 이 단추는 항상 보이며, 같은 주차의 앞 쪽에서 성공한 실행 기록(이 브라우저에 8시간 보관되고 새 탭에서도 유효하다)이 없으면 안내 문구가 나온다. 그때는 앞 쪽 편집기의 코드를 복사해 이 쪽 편집기 맨 위에 붙여 넣고 실행한다.
  4. 한 번의 실행은 15초를 넘기면 멈추고 환경이 초기화된다. 다음 실행 때 이 쪽에서 성공했던 코드가 자동으로 다시 실행되어 복원된다. 무한 반복이나 종료 조건(기저 조건) 누락이 없는지 확인한다.
  5. 골격의 ____1____ 같은 자리가 채울 곳이다. 이 쪽의 빈칸은 ①~③이다. 채우지 않고 실행하면 NameError: name '____1____' is not defined가 나오는데, 아직 채울 곳이 남아 있다는 뜻이다. 그 밖의 NameError는 아직 정의(실행)하지 않은 이름을 썼다는 뜻이다.
  6. 정답과 기대 값은 이 쪽 끝의 닫힌 확인 상자에만 있다. 점검은 정의대로 구한 값과 내 결과를 비교한다. 점검이 실패하면 AssertionError와 함께 어느 입력에서 틀렸는지 나온다. 값은 내가 실행해서 확인하고 활동지에 쓴다.
  7. 편집기에 둔 코드는 위쪽 [저장(JSON)]에 함께 담겨 제출된다. 따로 .py 파일을 내지 않는다.

A7 · 같은 값을 세 가지 방식으로 구하고 횟수 재기11분 · 개인

산출물: ① ~ ③ 완성 코드, 호출 횟수 예측-실제 표(활동지 2부 A7 칸)

약속 · 세 가지 방식
  • fib_naive는 정의 그대로 재귀로 구한다(제공). 전역 변수 calls가 함수가 불린 횟수를 센다.
  • fib_memo(n, memo)는 재귀로 풀되 한 번 계산한 값을 사전 memo에 적어 둔다. 호출하는 쪽이 빈 사전 {}을 만들어 넘긴다.
  • fib_tab(n)은 작은 값부터 표 dp를 채워 올라간다. 전역 변수 steps가 표의 칸을 채운 횟수를 센다.
  • 이 파일에서 functools는 쓰지 않는다. 직접 구현이 먼저이다.
학습 내용 · 세 함수가 하는 일과 횟수 예측하는 방법
  • fib_memo의 memo는 푼 답을 적어 두는 dict이다. 호출하는 쪽이 만든 빈 dict {}를 재귀 호출이 계속 넘겨 받으므로 한 번의 바깥 호출 안에서는 같은 dict가 쓰인다. 빈칸 ①은 “n의 답이 이미 적혀 있는가”를 묻는 조건이고, ②는 A3에서 손으로 한 규칙대로 작은 두 문제의 답을 합치는 식이다.
  • fib_tab의 dp[i]는 fib(i)의 값이다. dp[0] = 0은 리스트를 0으로 채울 때 정해지고 dp[1] = 1은 코드가 적는다. i를 2부터 n까지 늘리며 채우므로 ③은 이미 채워 둔 앞쪽 칸을 쓴다.
  • 세는 값이 다르다. fib_naive와 fib_memo는 함수가 불린 횟수(calls)를, fib_tab은 for문이 칸을 채운 횟수(steps)를 센다. 비교할 때 이 차이를 기억한다.
  • 예측하는 방법 순수 재귀는 A2에서 fib(6), fib(7)의 호출 수가 어떻게 늘었는지 보고 n = 20, 30으로 이어 본다. 메모는 A3에서 센 호출 수가 n과 어떤 관계였는지, 표는 for문이 몇 번 도는지 센다. 정확한 값이 아니라 자릿수 어림이면 충분하다. fib_naive(30)은 몇 초 걸릴 수 있다.
  • 값 세 개가 같은지는 assert 점검이 확인한다. 점검이 통과해야 횟수를 잰다.

제공 코드와 골격

실행 순서 ① [예시 코드]에서 A7-1(제공 코드)과 A7-2(뼈대)를 이 순서로 편집기에 추가한다. ② ____N____ 자리를 채우고 [▶ 실행]한다(정의만 있어서 출력은 없어도 된다). ③ A7-3(점검)을 맨 아래에 추가해 실행한다. “A7 점검 통과”가 나오면 된다. ④ 점검이 통과한 뒤 A7-4(예측 후 실행)를 맨 아래에 추가해 실제 값을 확인한다.

# A7: 피보나치 세 가지 방식. calls와 steps로 일한 횟수를 센다.
calls = 0                      # 시작 상태: 0
steps = 0                      # 시작 상태: 0

# 재귀 함수는 자기 자신을 다시 부르는 함수이다.
def fib_naive(n):
    global calls  # 함수 밖 변수 calls를 고친다는 선언
    calls += 1    # 불릴 때마다 1 센다
    if n < 2:     # 더 쪼갤 수 없는 가장 작은 경우
        return n  # 재귀를 멈추는 곳
    return fib_naive(n - 1) + fib_naive(n - 2)  # 작은 두 문제의 답을 더한다
def fib_memo(n, memo):         # memo: 푼 답을 적어 두는 dict
    global calls               # 함수 밖 변수 calls를 고친다는 선언
    calls += 1                 # 호출 횟수를 센다
    if ____1____:                    # ① 이미 계산했다면 바로 돌려준다
        return memo[n]         # dict에서 키 n의 값을 꺼낸다
    if n < 2:                  # 가장 작은 경우
        result = n             # 가장 작은 경우의 답
    else:
        result = ____2____           # ② 작은 문제 두 개를 풀어 합친다
    memo[n] = result           # 구한 답을 dict에 적어 둔다
    return result

def fib_tab(n):                # 표(리스트)를 앞에서부터 채운다
    global steps               # 반복 횟수를 세는 변수
    if n < 2:
        return n
    dp = [0] * (n + 1)         # 0이 n+1개 든 리스트(표)
    dp[1] = 1                  # 1번 칸 값을 미리 적는다
    for i in range(2, n + 1):  # i = 2, 3, ..., n 순서로 반복
        steps += 1             # 칸을 하나 채울 때마다 1 센다
        dp[i] = ____3____            # ③ 앞의 두 칸에서 만든다
    return dp[n]               # 표의 마지막 칸이 답이다

Tab 키는 4칸 들여쓰기이고 Ctrl(⌘)+Enter는 실행이다. 다음 칸으로 이동하려면 Esc를 누른 뒤 Tab을 누른다.

점검

# A7 점검: 닫힌 식(비네 공식)으로 구한 값과 내 결과를 비교한다.
# 비네 공식: 피보나치 수를 식 하나로 구한다(검산용).
def closed_form(n):
    phi = (1 + 5 ** 0.5) / 2
    return round(phi ** n / 5 ** 0.5)  # 실수 오차는 반올림으로 정리한다

for n in range(0, 26):                 # n = 0~25를 모두 검사한다
    want = closed_form(n)
    # assert 조건, 메시지: 조건이 거짓이면 메시지를 띄우고 멈춘다.
    # 멈췄다면 그 줄의 함수가 닫힌 식과 다른 값을 냈다는 뜻이다.
    assert fib_naive(n) == want, "fib_naive(%d)=%r 인데 닫힌 식은 %r이다" % (n, fib_naive(n), want)
    # 메모 방식. 호출마다 빈 dict {}를 새로 준다.
    got = fib_memo(n, {})
    assert got == want, "fib_memo(%d, {})=%r 인데 닫힌 식은 %r이다" % (n, got, want)
    # 표 방식.
    got = fib_tab(n)
    assert got == want, "fib_tab(%d)=%r 인데 닫힌 식은 %r이다" % (n, got, want)
shared = {}                          # 한 메모를 여러 번 불러도 맞아야 한다
for n in (10, 5, 25, 3, 0, 1):
    got = fib_memo(n, shared)
    assert got == closed_form(n), "공유한 메모로 fib_memo(%d)=%r 인데 닫힌 식은 %r이다" % (n, got, closed_form(n))
print("A7 점검 통과")                      # 위 검사를 모두 통과해야 출력된다

예측 후 실행

n = 20과 30에서 세 방식의 횟수를 먼저 활동지에 예측하고, 아래 코드를 실행해 실제 값을 쓴다. fib_naive(30)은 몇 초 걸릴 수 있다.

# 예측을 활동지에 먼저 적은 뒤 실행한다.
for n in (20, 30):     # n = 20, 30으로 두 번 실행한다
    calls = 0
    v1 = fib_naive(n)  # 반환값
    c1 = calls         # 이 방식이 불린 횟수를 적어 둔다
    calls = 0
    v2 = fib_memo(n, {})
    c2 = calls
    steps = 0
    v3 = fib_tab(n)
    c3 = steps         # 표를 채운 반복 횟수를 적어 둔다
    # 값 세 개와 센 횟수 세 개를 한 줄에 출력한다.
    print("n =", n, " 값:", v1, v2, v3, " fib_naive 호출:", c1, " fib_memo 호출:", c2, " fib_tab 반복:", c3)

예측은 실행 전에 활동지 2부에 쓰고, 점검이 통과한 뒤 같은 표의 ‘실제’ 칸에 값을 쓴다. 이 주의 실습 과제는 A8 시작 때 student_code_lab_part2에서 안내한다.
