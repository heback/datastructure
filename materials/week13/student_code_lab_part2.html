# A8 점검: 정의대로 한 방법과 내 결과를 비교한다.
def greedy_by_definition(coins, amount):       # 남은 금액 이하인 가장 큰 동전을 계속 낸다
    n = 0
    while amount > 0:       # 남은 금액이 있는 동안 반복한다
        biggest = max(c for c in coins if c <= amount)  # 낼 수 있는 동전 중 가장 큰 것
        amount -= biggest   # 빼서 다시 amount에 저장한다
        n += 1              # 동전 1개를 썼다
    return n

def fewest_by_layers(coins, amount):           # 동전을 한 개씩 늘려 가며 처음으로 만들어지는 개수를 센다
    seen = {0}              # set: 이미 만든 금액 모음(중복 없음)
    frontier = [0]          # 이번 단계에서 만든 금액들
    n = 0
    while frontier:
        if amount in seen:  # 목표를 만들었으면 지금 n이 답이다
            return n
        nxt = []            # 다음 단계 금액을 모을 리스트
        for s in frontier:
            for c in coins:
                if s + c <= amount and s + c not in seen:
                    seen.add(s + c)
                    nxt.append(s + c)
        frontier = nxt
        n += 1
    return -1               # 끝까지 못 만들면 -1

# 동전 체계 여러 개 x 금액 0~60을 모두 검사한다.
for coins in ([1, 3, 4], [1, 4, 6], [1, 5, 10, 20, 25], [1, 10, 50, 100, 500], [1, 2], [1]):
    for a in range(0, 61):
        # 내 결과와 정의대로 낸 결과
        got, want = greedy_coins(coins, a), greedy_by_definition(coins, a)
        # 실패하면 내 greedy_coins가 정의대로 낸 개수와 다르다는 뜻이다.
        assert got == want, "greedy_coins(%r, %d)=%r 인데 정의대로 하면 %r이다" % (coins, a, got, want)
# 이번에는 내 dp_coins를 검사한다.

실습 과제 안내 · DP 테이블 설계와 반례 도출A8 착수 · A9·A11 이어짐 · A14 마무리 · 잔여는 주간 과제

과제 (함수 3개 + 서술 1건)
  • min_coins(coins, amount): 동전을 무한히 쓸 수 있을 때 amount를 만드는 최소 동전 개수. 만들 수 없으면 -1, amount == 0이면 0이다. coins는 정렬되어 있다고 가정하지 않고 1이 없을 수 있다. 1차원 DP 표를 설계해 구현한다.
  • grid_paths(grid): 0 = 통행, 1 = 막힘인 R×C 격자에서 좌상단에서 우하단까지 오른쪽·아래로만 가는 경로 수. 시작이나 도착이 막혀 있으면 0이다. 2차원 DP 표를 설계해 구현한다.
  • greedy_counterexample(coins): coins는 오름차순이고 1을 포함한다. 큰 동전부터 쓰는 방식의 개수가 최소 개수와 다른 가장 작은 금액(반례)을 돌려준다. 검사 범위는 1 ~ 2×가장 큰 동전이고, 없으면 None이다.
  • 서술(코드 아님, 3~5문장): 내가 설계한 동전 체계 1개(반례가 나오는 체계)에 대해 “이 금액에서 큰 동전부터 쓰는 방식은 몇 개, 최적은 몇 개이며 어떤 조합인가”를 금액·두 조합·개수로 쓰고, min_coins의 상태 정의·전이·초기값을 내 말로 적는다.
  • A8에서 착수하고, A9·A11(2차시와 3차시)에서 이어 쓰며, A14에서 마무리 점검한다. 미완 부분은 주간 과제로 이어진다.

기준은 “AI에게 무엇을 시켰는가”이다. 개념·용어·오류 원인을 묻는 것은 허용이고, 과제 요구사항이나 완성된 구현·설계 판단 자체를 AI에게 시켜 결과물을 받아 제출하는 것은 금지이다.

허용 — 성찰일지에 간단히 기록
  • “메모이제이션과 타뷸레이션은 무엇이 달라?”, “탐욕 알고리즘이 최적이 되려면 어떤 성질이 필요해?” 같은 개념·용어 질의
  • “RecursionError: maximum recursion depth exceeded가 무슨 뜻이야?”, “IndexError: list index out of range가 왜 나오는지 해설” 같은 오류 메시지 해설
  • “dynamic programming이라는 이름은 어디서 유래했어?” 같은 용어 번역·개념 요약, 수업 자료 복습 질문(코드는 받지 않음)
  • 내 코드 결과가 TEST와 다를 때 원인 힌트만 요청(수정은 직접 한다)
조건부 허용 — 출처와 반영 여부를 성찰일지에 반드시 기록
  • 완성한 구현에 대한 복잡도 검토 요청(예: “이 구현이 정말 O(amount × 동전 수)가 맞는지 검토해줘”). 복잡도 분석을 대신 세우게 하는 것이 아니라 내가 쓴 분석의 검토만 맡긴다
  • 엣지 케이스 브레인스토밍(amount = 0, 만들 수 없는 금액, 동전 1개, 시작이나 도착이 막힌 격자, 1×1 격자)
  • 내가 쓴 코드의 경계 조건·성능 검토 요청(수정은 직접 한다)
  • 내 코드와 서술의 개선 아이디어 제안 요청(제안만 참고하고 코드와 문장은 직접 다시 작성)
  • 기록 예: “AI가 amount = 0 케이스를 제안 → 채택/미채택, 이유”
금지 — 적발 시 계획서의 위반 처리방안 적용
  • 과제 문장(“최소 동전 개수를 구하는 함수, 격자 경로 수를 구하는 함수, 큰 동전부터 쓰는 방식과 최솟값이 달라지는 가장 작은 금액(반례)을 구하는 함수를 작성하라”)을 그대로 입력해 전체 코드 생성
  • AI가 쓴 min_coins/grid_paths/greedy_counterexample를 그대로, 또는 변수명만 바꿔 제출
  • 상태 정의·전이 방정식·초기값·계산 순서 등 DP 설계 판단, 반례가 되는 동전 체계·금액을 AI가 대신 찾음
