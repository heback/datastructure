큰 동전부터 내 보기

동전 1원, 5원, 10원으로 17원을 만든다. 큰 동전부터 쓸 수 있는 만큼 쓰고 남은 금액을 넘긴다.

동전 [1, 5, 10], 17원
10원: 1개 쓰고, 남은 금액 7원
 5원: 1개 쓰고, 남은 금액 2원
 1원: 2개 쓰고, 남은 금액 0원   → 모두 4개

28원이면 10원 동전을 몇 개 쓰고 얼마가 남을까?

28에서 10을 2번 빼면 8이 남는다.

몫, 나머지, 거꾸로 훑기

몫은 //, 나머지는 %로 구한다. reversed(목록)은 뒤에서부터 하나씩 내준다.

큰 동전 함수 채우기 ④⑤

greedy_coins(coins, amount)의 ④⑤를 채우자. 큰 동전부터 쓴 개수를 돌려주는 함수이다. 먼저 활동지 2부 A8의 6원 예측 칸을 채워 두자.

④는 큰 동전부터 훑는 목록, ⑤는 남은 금액이다. 실행하면 greedy_coins: 3 뒤에 NameError: ____6____이 나오는 것이 정상이다. dp_coins는 뒤 걸음에서 채운다.

아래에서 1걸음의 17원을 확인하자.

만들 수 없는 금액

dp[a]는 a원을 만드는 최소 개수이다. 동전이 [2, 5]뿐이면 1원과 3원은 만들 수 없다. 이런 칸에는 INF(무한대, 아주 큰 값)를 적는다.

동전 [2, 5]
a       0    1    2    3    4    5
dp[a]   0    INF  1    INF  2    1

dp[3]이 INF인 까닭은?

2와 5를 몇 개 합쳐도 3이 되지 않는다.

표 시작하기 ⑥⑦

표는 모든 칸을 INF로 시작하고 0원만 0개로 정한다. [x] * k는 x를 k개 늘어놓은 리스트이다.

아래 코드의 둘째 줄에는 무엇이 나올까?

위 편집기의 dp_coins에서 ⑥⑦을 채우자. ⑥은 이미 있는 이름 INF를 쓴다.

칸 채우기 ⑧⑨

동전 c를 마지막으로 쓰면 a원의 개수는 dp[a - c] + 1이다. 이 후보가 지금의 dp[a]보다 작을 때만 바꾼다.

위 표에서 a = 5, c = 5이면 후보는 얼마일까?

dp[0] + 1 = 1이다.

⑧은 후보가 dp[a]보다 작은지 묻는 조건, ⑨는 dp[a]에 넣을 값이다. ⑧을 먼저 정하면 ⑨는 같은 후보이다.

점검하고 6원 비교하기

[✔ 점검]을 누르자. A8 점검 통과가 나오면 완성이다.

실행 때 맨 끝에 나온 6원 결과 두 줄을 ‘실제’ 칸에 쓴다.

끝까지 막혔다면 · 빈칸 답

④ reversed(coins) ⑤ amount % c ⑥ INF ⑦ 0 ⑧ dp[a - c] + 1 < dp[a] ⑨ dp[a - c] + 1

선택 도전: 12주차의 bisect_right(coins, a) - 1은 a 이하의 가장 큰 동전의 자리를 준다. 이 식으로 greedy_coins를 다시 써 보아도 된다.

실습 과제 안내 · DP 테이블 설계와 반례 도출A8 착수 · A9·A11 이어짐 · A14 마무리 · 잔여는 주간 과제

무엇을 만드는가
  • min_coins(coins, amount): 동전을 무한히 쓸 수 있을 때 amount를 만드는 최소 동전 개수를 돌려준다. 만들 수 없으면 -1, amount == 0이면 0이다. coins는 정렬되어 있다고 가정하지 않고 1이 없을 수 있다. 1차원 DP 표로 구현한다.
  • grid_paths(grid): 0 = 통행, 1 = 막힘인 R×C 격자에서 좌상단에서 우하단까지 오른쪽·아래로만 가는 경로 수를 돌려준다. 시작이나 도착이 막혀 있으면 0이다. 2차원 DP 표로 구현한다.
  • greedy_counterexample(coins): coins는 오름차순이고 1을 포함한다. 큰 동전부터 쓴 개수가 최소 개수와 다른 가장 작은 금액(반례)을 돌려준다. 검사 범위는 1 ~ 2×가장 큰 동전이고, 없으면 None이다.
  • 서술(3~5문장): 반례가 나오는 동전 체계 1개를 내가 설계해 금액·두 조합·개수를 쓰고, min_coins의 상태 정의·전이·초기값을 내 말로 적는다.

기준은 “AI에게 무엇을 시켰는가”이다. 개념·용어·오류 원인을 묻는 것은 허용이고, 과제 요구사항·완성된 구현·설계 판단을 시켜 결과물을 받아 제출하는 것은 금지이다.

허용
  • “메모이제이션과 타뷸레이션은 무엇이 달라?”, “탐욕 알고리즘이 최적이 되려면 어떤 성질이 필요해?” 같은 개념·용어 질의

  • “dynamic programming이라는 이름은 어디서 유래했어?” 같은 용어 번역·개념 요약, 수업 자료 복습 질문(코드는 받지 않음)
  • 내 코드 결과가 TEST와 다를 때 원인 힌트만 요청(수정은 직접 한다)

  • 엣지 케이스 브레인스토밍(amount = 0, 만들 수 없는 금액, 동전 1개, 시작이나 도착이 막힌 격자, 1×1 격자)
  • 내 코드의 경계 조건·성능 검토 요청(수정은 직접 한다)
  • 내 코드와 서술의 개선 아이디어 제안 요청(제안만 참고하고 직접 다시 작성)
금지 — 적발 시 계획서의 위반 처리방안 적용
  • 과제 문장(“최소 동전 개수를 구하는 함수, 격자 경로 수를 구하는 함수, 큰 동전부터 쓰는 방식과 최솟값이 달라지는 가장 작은 금액(반례)을 구하는 함수를 작성하라”)을 그대로 입력해 전체 코드 생성
  • AI가 쓴 min_coins/grid_paths/greedy_counterexample를 그대로, 또는 변수명만 바꿔 제출
  • 상태 정의·전이 방정식·초기값·계산 순서 등 DP 설계 판단, 반례가 되는 동전 체계·금액을 AI가 대신 찾음
  • 복잡도 분석이나 구현 계획(상태 정의와 목표 비용 포함)을 AI에게 대신 세우게 하여 제출
  • 상태 정의·전이 설계나 반례 증명 문장을 AI가 대신 쓰게 하여 제출
