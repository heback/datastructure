사용법#how

  1. 코드는 입력란의 편집기에서 쓰고 [▶ 실행](Ctrl 또는 ⌘+Enter)으로 확인한다. 입력란 위의 [예시 코드] 단추를 누르면 그 활동의 공통 코드·골격·테스트가 나온다. 필요한 블록의 [편집기에 추가]를 눌러 위에서 아래 순서(공통 코드 → 골격 → 테스트)로 편집기에 붙인다. 골격의 raise 줄은 지우고 내 코드를 쓴다.
  2. 이 쪽의 실행 환경은 앞 쪽과 따로이다. A10 코드는 [예시 코드]의 공통 코드(import, G1_EDGES, make_g1)를 편집기에 먼저 추가해 실행한 뒤 이어서 쓴다. 같은 쪽의 편집기들은 환경을 공유하므로 앞에서 실행한 함수와 변수를 뒤에서 쓸 수 있다. 다른 쪽에서 만든 코드가 필요하면 그 쪽에서 실행해 성공시킨 뒤 이 쪽의 [앞 쪽 코드 불러오기] 단추를 누른다.
  3. NameError는 아직 정의하지 않은 이름을 쓴 것이다. AssertionError는 아직 틀린 곳이 있다는 뜻이고, NotImplementedError는 채울 곳이 남았다는 뜻이다. 한 번 실행이 15초를 넘으면 멈추고 환경이 초기화된다.
  4. A10의 예측용 코드는 실행하기 전에 활동지 3부 A10의 예측 칸을 먼저 채우고, 실행한 값을 실제 칸에 쓴다. 이 파일에는 출력 값이 적혀 있지 않다.
  5. A13의 과제 점검은 내가 쓴 build_graph, neighbors를 점검 입력 뒤에 붙여 실행한다. 기대 값은 이 파일에 없고, 테스트가 입력에서 계산한 참조와 비교한다. A13의 접힌 블록(“A13 점검 직전에 교사 지시 후 펼침”)은 교사가 지시할 때 펼친다.
  6. 편집기에 쓴 내용은 [저장(JSON)] 때 함께 제출된다.

A10 · 이웃 반환 함수 두 가지14분 · 짝

같은 일을 하는 이웃 반환 함수를 두 가지로 만든다. (가)는 이웃을 리스트로 만들어 돌려주고, (나)는 이웃을 요청할 때마다 하나씩 내준다. 교사가 yield의 문법을 설명한 뒤 (나)를 완성한다. (가)와 (나)를 각각 완성한다. 호출하는 쪽 코드 for v in neighbors_gen(g, u)가 (가)와 (나)에서 같은지도 확인한다.

import inspect  # 코드의 종류를 검사하는 표준 라이브러리이다
g = make_g1()  # 새로 만든 G1로 시험한다
fails = []
for u in list(g):  # 모든 노드 u를 하나씩 확인한다
    # (가) 확인: 리스트이고 g[u]와 값이 같은가
    if not isinstance(neighbors_list(g, u), list) or neighbors_list(g, u) != list(g[u]):
        fails.append("(가) neighbors_list(%s)" % u)
    # (가) 확인: is는 같은 객체인지 비교한다. g의 리스트 자체는 아니어야 한다.
    if neighbors_list(g, u) is g[u]:
        fails.append("(가) neighbors_list(%s)가 g의 리스트를 그대로 돌려준다(새 리스트여야 한다)" % u)
    it = neighbors_gen(g, u)
    # (나) 확인: 제네레이터 객체인가
    if not inspect.isgenerator(it):
        fails.append("(나) neighbors_gen(%s)이 제네레이터가 아니다" % u)
        continue
    got = list(it)  # 내준 값을 모두 모아 리스트로 만든다
    if got != list(g[u]):  # (가)의 목록과 값이 같은가
        fails.append("(나) neighbors_gen(%s)의 값이 다르다" % u)
    if list(it) != []:
        fails.append("(나) 다 쓴 제네레이터가 비어 있지 않다")
    # 호출하는 쪽의 for 문 결과도 (가)와 비교한다.
    for_loop = []
    for v in neighbors_gen(g, u):
        for_loop.append(v)
    if for_loop != neighbors_list(g, u):
        fails.append("호출하는 쪽 for 문의 결과가 (가)와 (나)에서 다르다")
# 모은 실패 이유를 한 줄씩 출력한다.
for f in fails:
    print("FAIL", f)
# 실패가 하나라도 있으면 AssertionError로 멈춘다.
assert not fails, "A10 테스트 실패: %s" % fails
print("A10 테스트 통과")

과제 안내 갱신 (이 파일에서 처음 안내한다)
  • build_graph(edges, directed=False)는 defaultdict(list)를 반환한다.
  • neighbors(g, u)는 yield를 쓰는 제네레이터여야 한다(이웃 리스트를 반환하면 안 된다).
  • 검증용으로 일반 dict나 리스트 기반 비교 코드를 직접 쓰는 것은 허용된다.

(가) 과제 마무리 점검 (8분)

# 확인용 함수: 간선 목록에서 기대하는 이웃 목록을 계산한다.
def expected(edges, directed):
    # 입력 간선 목록에서 계산한 참조 목록(각 노드의 이웃을 간선이 나온 순서로 쌓는다)
    if directed:
        return {n: [b for a, b in edges if a == n] for n in {a for a, b in edges}}
    nodes = {a for a, b in edges} | {b for a, b in edges}
    return {n: [b if a == n else a for a, b in edges if n in (a, b)] for n in nodes}

# 두 노선도를 차례로 만들어 수를 센다.

조건부 허용 — 출처와 반영 여부를 성찰일지에 반드시 기록
  • 완성한 구현의 엣지 케이스 브레인스토밍(빈 간선 목록, 고립 노드, 중복 간선, 방향/무방향, 없는 노드 질의)
  • 내가 쓴 neighbors의 동작을 엣지 케이스별로 검토 요청(수정은 직접 한다)
  • 내 코드의 개선 아이디어 제안 요청(제안만 참고하고 코드는 직접 다시 작성)
  • 내가 쓴 구현의 시간·공간 복잡도 검토 요청(복잡도는 내가 먼저 쓴 뒤 검토만 받고, 고쳐 쓰기는 직접 한다)
  • 기록 예: “AI가 고립 노드 처리를 제안 → 채택/미채택, 이유”, “AI가 복잡도 근거 문장이 모호하다고 지적 → 채택/미채택, 이유”
금지 — 적발 시 계획서의 위반 처리방안 적용
  • 과제 문장(“defaultdict(list)로 그래프를 만들고 제네레이터로 이웃을 반환하라”)을 그대로 입력해 전체 코드 생성
  • AI가 쓴 build_graph/neighbors를 그대로, 또는 변수명만 바꿔 제출
  • 두 표현 중 무엇을 쓸지, 예외 상황을 어떻게 처리할지 등 설계 판단을 AI가 대신 내림
  • 복잡도 분석이나 구현 계획을 AI에게 대신 세우게 하여 제출
  • 성찰일지 AI 대필
수업 운영 규칙(금지 목록과 별개) 수업 중 A6~A10·A13~A14는 AI 도움 없이 수행한다. A14 형성평가는 AI를 쓰지 않는 시험 상황으로 운영하며, 위 위반 처리(감점 등)는 형성평가에 적용하지 않는다. 주간 과제를 제출할 때 위 3단계가 적용된다. A15에서 성찰일지에 AI 활용 내역을 쓰는 방법을 다시 안내한다.
