사용법#how

  1. 코드는 입력란의 편집기에서 쓰고 [▶ 실행](Ctrl 또는 ⌘+Enter)으로 확인한다. 입력란 위의 [예시 코드] 단추를 누르면 그 활동의 공통 코드·골격·테스트가 나온다. 필요한 블록의 [편집기에 추가]를 눌러 위에서 아래 순서(공통 코드 → 골격 → 테스트)로 편집기에 붙인다.

A6 · 인접 행렬 코드로 만들기12분 · 개인

A2에서 손으로 만든 6×6 표를 코드로 만든다. 행렬은 칸 번호가 정수여야 하므로 노드 A~F를 0~5로 바꾸는 번호표(MAP)를 쓴다. make_matrix(빈칸 ①)와 add_edge(빈칸 ②)를 완성하고, 만든 행렬을 활동지 2부 A6의 손 표와 대조한다.

학습 내용 · 리스트의 리스트와 칸 번호
  • 행렬은 리스트 안에 행(리스트)을 넣어 만든다. m[i][j]는 i번 행의 j번 칸이고 0부터 센다. [0] * 3은 [0, 0, 0]이다.
m = [[0, 0], [0, 0]]
m[0][1] = 5
print(m)   # [[0, 5], [0, 0]]
  • 순서는 ① 행 하나를 만든다 ② 그 행을 N개 모은다 ③ add_edge에서 간선 하나가 표의 몇 칸을 바꾸는지 A2의 표로 확인한다 ④ 자체 테스트를 돌려 FAIL 줄을 읽는다.

자체 테스트 (G1)

N = len(MAP)  # 노드 수이다. MAP의 항목 개수와 같다.
m = make_matrix(N)  # 내가 만든 함수로 행렬을 만든다
for a, b in G1_EDGES:  # 간선을 하나씩 꺼내 a, b에 담는다
    add_edge(m, MAP[a], MAP[b])  # 이름을 번호로 바꿔 간선을 기록한다

# 참조 행렬: 간선 목록에서 직접 계산한다(A2에서 손으로 만든 표와 비교하는 용도).
# 집합 {...}은 중복 없는 모음이다. |는 두 집합을 합친다.
pairs = {(MAP[a], MAP[b]) for a, b in G1_EDGES} | {(MAP[b], MAP[a]) for a, b in G1_EDGES}
# [식 for 변수 in 범위]는 반복해 리스트를 만드는 컴프리헨션이다.
ref = [[1 if (i, j) in pairs else 0 for j in range(N)] for i in range(N)]

fails = []  # 실패 이유를 모으는 빈 리스트이다
# 확인 1: 행 수와 각 행의 길이가 모두 N인가
if len(m) != N or any(len(row) != N for row in m):
    fails.append("행렬의 크기가 N x N이 아니다")
# 확인 2: 내 행렬이 확인용 표와 같은가
if m != ref:
    fails.append("행렬이 간선 목록에서 계산한 참조 행렬과 다르다")
# 확인 3: 모든 (i, j)에서 m[i][j]와 m[j][i]가 같은가
if any(m[i][j] != m[j][i] for i in range(N) for j in range(N)):
    fails.append("행렬이 기대와 다르다")
# 확인 4: 작은 행렬 t의 한 칸만 바꿨을 때 합이 1인가
t = make_matrix(3)
t[0][1] = 1
if sum(sum(row) for row in t) != 1:
    fails.append("작은 행렬 t의 값이 기대와 다르다")
# 모은 실패 이유를 한 줄씩 출력한다.
for f in fails:
    print("FAIL", f)
# fails가 비어 있지 않으면 AssertionError로 멈춘다. 위 FAIL 줄을 읽는다.
assert not fails, "A6 테스트 실패: %s" % fails
# 여기까지 실행되면 확인 1~4를 모두 통과한 것이다.
print("A6 테스트 통과")
행렬 전체가 대칭인지 코드로 확인하는 방법을 생각해 본다. 노드 이름이 "A"일 때 칸 번호를 어떻게 아는지도 활동지에 쓴다.

# A7 확인: 위에서 만든 g(G1, 무방향)와 gw(W, 방향)가 손 목록과 같은지 계산식으로 비교한다.
# globals()는 지금까지 만든 변수 이름들이다. g, gw가 있는지 본다.
assert "g" in globals() and "gw" in globals(), "먼저 g(G1)와 gw(W)를 만든다"
# 확인용 함수: 간선 목록에서 이웃 목록을 계산한다.
def ref_undirected(edges):
    nodes = {a for a, b in edges} | {b for a, b in edges}
    return {n: [b if a == n else a for a, b in edges if n in (a, b)] for n in nodes}

# 방향 그래프용: 간선 (a, b)는 a의 이웃에만 b를 넣는다.
def ref_directed(edges):
    return {n: [b for a, b in edges if a == n] for n in {a for a, b in edges}}

# dict(...)로 감싸 같은 종류로 맞춘 뒤 비교한다.
assert dict(g) == ref_undirected(G1_EDGES), "G1 목록이 간선 목록에서 계산한 참조 목록과 다르다"
# 다르면 W 목록 구축 코드를 다시 본다.
assert dict(gw) == ref_directed(W_EDGES), "W 목록이 간선 목록에서 계산한 참조 목록과 다르다"
# 두 assert를 통과하면 여기까지 실행된다.
print("A7 확인 통과")

과제
  • build_graph(edges, directed=False)를 구현한다. edges는 (u, v) 쌍의 리스트이다. directed=False이면 무방향(양쪽 노드의 이웃 목록에 모두 넣는다), True이면 u→v 방향만 넣는다. 반환값은 노드마다 이웃 목록을 담은 dict 계열 자료이고, g[u]가 u의 이웃 목록이다. 정확한 자료형은 A7에서 도구를 확인한 뒤 같은 과제 안내(실습 코드 3부)에서 적는다. 이웃은 간선이 입력된 순서로 쌓는다.
  • neighbors(g, u)를 구현한다. 노드 u의 이웃을 돌려주는 함수이다. 반환 방식과 추가 조건은 3차시 A10 시작 때 배포하는 student_code_lab_part3에서 안내한다.
  • 노드 이름은 문자열이나 숫자이다. 중복 간선과 자기 자신으로의 간선(u, u)은 입력으로 다루지 않는다. 간선이 없는 고립 노드는 간선 목록만으로 만들 수 없는 것이 정상이다.
  • A7에서 착수하고, A10(3차시)에서 neighbors를 탐구하며, A13은 이 과제의 마무리 점검이다. A13의 지하철 노선도 전이 연습은 과제 제출물이 아니며 채점하지 않는다. 미완 부분은 주간 과제로 이어진다.

허용
  • 이 과제에서 쓰는 자료구조가 무엇이고 어떤 때 쓰는지 묻는 개념·문법 질의
  • 용어 번역·개념 요약, 수업 자료 복습 질문
  • “NameError: name ‘x’ is not defined가 왜 나와?” 같은 오류 메시지 해설
  • 인접 행렬과 인접 리스트가 보통 어디에 쓰이는지 용어와 설계 배경을 묻는 설명
  • 내 코드의 결과가 점검 케이스와 다를 때, 원인에 대한 힌트만 요청(코드는 요청하지 않음)
조건부 허용
  • 내가 완성한 구현의 엣지 케이스 브레인스토밍(빈 간선 목록, 고립 노드, 중복 간선, 방향/무방향, 없는 노드 질의)
  • 내가 쓴 함수의 동작을 검토해 달라는 요청(수정은 직접 한다)
  • 내 코드의 개선 아이디어 제안 요청(제안만 참고하고 코드는 직접 다시 작성)
  • 내가 쓴 구현의 시간·공간 복잡도 검토 요청(복잡도는 내가 먼저 쓴 뒤 검토만 받고, 고쳐 쓰기는 직접 한다)
  • 기록 예: “AI가 고립 노드 처리를 제안 → 채택/미채택, 이유”, “AI가 복잡도 근거 문장이 모호하다고 지적 → 채택/미채택, 이유”
금지 — 적발 시 계획서의 위반 처리방안 적용
  • 과제 문장을 그대로 입력해 전체 코드 생성
  • AI가 쓴 build_graph, neighbors를 그대로, 또는 변수명만 바꿔 제출
  • 두 표현 중 무엇을 쓸지, 어떻게 만들지 등 설계 판단을 AI가 대신 내림
  • 복잡도 분석이나 구현 계획을 AI에게 대신 세우게 하여 제출
수업 운영 규칙(금지 목록과 별개) 수업 중 A6~A10·A13~A14는 AI 도움 없이 수행한다. A14 형성평가는 AI를 쓰지 않는 시험 상황으로 운영하며, 위 위반 처리(감점 등)는 형성평가에 적용하지 않는다. 주간 과제를 제출할 때 위 3단계가 적용된다.
