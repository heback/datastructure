사용법#how

  • 편집기에는 필요한 코드가 미리 들어 있다. ____1____ 같은 자리를 채우고 [▶ 실행]을 누른다.
  • [✔ 점검]은 내 코드가 맞는지 확인해 준다. [처음 코드로]는 편집기를 처음 상태로 되돌린다.
  • 편집기에 쓴 내용은 자동으로 보관된다. 다 했으면 위의 [저장(JSON)]으로 제출 파일을 만든다.
단축키와 오류가 날 때
  • Ctrl(⌘)+Enter는 실행, Tab은 들여쓰기, Shift+Tab은 내어쓰기이다.
  • 오류가 나면 맨 아래 줄부터 읽는다. NameError는 아직 정의하지 않은 이름을 썼다는 뜻이고, AssertionError는 점검이 틀린 곳을 찾았다는 뜻이다.
  • 같은 쪽의 편집기들은 파이썬 환경을 공유한다. 앞에서 실행한 함수와 변수를 뒤에서 쓸 수 있다. 한 번 실행이 15초를 넘으면 멈추고 환경이 초기화된다.
  • A6 점검은 두 값을 비교하지만 출력하지는 않는다. 틀리면 for row in m: print(row)로 내 표를 찍어 활동지의 손 표와 견준다.

A6 · 인접 행렬 코드로 만들기12분 · 개인

활동지에서 손으로 만든 G1의 표를 이제 코드가 만들게 하자.

표는 리스트의 리스트

3×3 표를 만들고 한 칸만 바꿔 보자. 아래 편집기를 [▶ 실행]하면 표가 세 줄로 나온다.

m[0][1]은 0번 줄의 1번 칸이다. 줄을 행이라 부르고, 줄과 칸 모두 0부터 센다.

m[2][0] = 1을 더 쓰면 새로 1이 되는 칸은?

앞 수가 줄(행) 번호, 뒤 수가 그 줄의 칸 번호이다. 둘 다 0부터 센다.

간선 하나는 칸 두 개

노드 A, B, C가 있는 작은 그래프에 간선 (A, B)를 기록한다. 노드 이름은 정수 번호가 아니므로 이름을 번호로 바꾸는 번호표(dict)를 쓴다.

이어진 사이는 방향이 없으므로 (A, B)와 (B, A) 두 칸에 모두 1을 쓴다.

이 표에 간선 (B, C)도 기록하면 1을 쓰는 칸은?

B행 C열과 C행 B열, 두 칸이다.

make_matrix 채우기

먼저 모든 칸이 0인 n×n 표를 만드는 make_matrix를 완성하자. 줄 하나는 [0] * n(예: [0] * 3은 [0, 0, 0])처럼 만든다. ①을 채우고 실행한다.

위쪽 제공 코드는 읽지 않아도 된다. 실행해도 아무것도 나오지 않는 것이 정상이다.

위 편집기를 실행한 뒤 이 칸을 실행하면 [0, 0, 0]이 세 줄 나와야 한다.

add_edge 채우기

같은 편집기의 ②와 ③을 채우자. 2걸음에서 본 대로 간선 하나는 두 칸에 쓴다. m[u][v]에서 u가 행, v가 열이다.

u, v는 노드 이름이 아니라 0~n-1 번호이다. 이름을 번호로 바꾸는 일은 점검 코드가 번호표 MAP으로 한다.

점검하기

[✔ 점검]을 누르면 G1의 표를 만들어 확인한다. A6 테스트 통과가 나오면 완성이다.

FAIL 줄이 나오면 크기가 다른지, 간선 목록에서 계산한 표와 다른지, 대칭이 깨졌는지를 알려 준다. 값은 보여 주지 않으니 다음 걸음처럼 표를 출력해 살핀다.

손 표와 견주기

F는 아무와도 이어져 있지 않다. 내 코드가 만든 표를 출력해 활동지의 손 표와 견주자. 줄과 칸은 A~F 순서이다.

A ─ B
│   │
C ─ D ─ E        F

출력된 표에서 F(5번)의 줄은 어떤 모습일까?

F의 간선이 없으므로 F행도 F열도 모두 0이다.

손 표와 같은지는 활동지 2부 A6에서 확인하고 기록한다.

끝까지 막혔다면 · 빈칸 답

① [0] * n ② m[u][v] = 1 ③ m[v][u] = 1

간선 목록에서 이 dict를 만드는 코드가 편집기에 들어 있다. 실행하기 전에 예측해 보자.

내 방법으로 고치기

같은 편집기에서 오류가 나지 않게 고쳐 보자. 성공하지 못해도 된다. 키를 미리 모두 만들려면 노드 이름을 먼저 알아야 한다. 간선만 주어지면 어떨까?

막혔다면 · 한 가지 방법

g[u]를 쓰기 전에 u가 g에 있는지 확인하고, 없으면 g[u] = []를 먼저 한다. v도 같다.

defaultdict 만나기

없는 키를 처음 쓰는 순간 빈 리스트를 만들어 주는 dict가 있다. 6주차에 쓴 defaultdict(int)의 친구인 defaultdict(list)이다.

마지막 줄은 무엇을 출력할까?

괄호 안에는 함수 자체인 list를 쓴다. list()나 []를 쓰면 TypeError: first argument must be callable or None이 난다.

만들 함수 2개
  • build_graph(edges, directed=False): edges는 (u, v) 쌍의 리스트이다. directed=False이면 양쪽 노드의 이웃 목록에 모두 넣고, True이면 u→v 한쪽만 넣는다. 돌려주는 값은 노드마다 이웃 목록을 담은 dict 계열 자료이고 g[u]가 u의 이웃 목록이다(정확한 자료형은 3부 A13에서 정해진다). 이웃은 간선이 입력된 순서로 쌓는다.
  • neighbors(g, u): 노드 u의 이웃을 돌려주는 함수이다. 반환 방식은 A10 시작 때 배포하는 student_code_lab_part3에서 안내한다.
  • 노드 이름은 문자열이나 숫자이다. 중복 간선과 자기 자신으로의 간선 (u, u)는 입력으로 다루지 않는다. 간선이 없는 고립 노드는 간선 목록만으로 만들 수 없는 것이 정상이다.
  • A7에서 착수하고, A10에서 neighbors를 탐구하며, A13에서 마무리 점검한다. A13의 지하철 노선도 전이 연습은 채점하지 않는다. 미완 부분은 주간 과제로 이어진다.

AI 활용 3단계 · 이 과제에 맞춘 예허용 · 조건부 허용 · 금지

기준은 “AI에게 무엇을 시켰는가”이다. 개념·문법·오류 원인을 묻는 것은 허용이고, 과제 요구사항이나 완성된 구현을 입력해 결과물(코드·글)을 받아 제출하는 것은 금지이다.

허용
  • 이 과제에서 쓰는 자료구조가 무엇이고 어떤 때 쓰는지 묻는 개념·문법 질의
  • 용어 번역·개념 요약, 수업 자료 복습 질문
  • “NameError: name ‘x’ is not defined가 왜 나와?” 같은 오류 메시지 해설
  • 인접 행렬과 인접 리스트가 보통 어디에 쓰이는지 묻는 용어·설계 배경 설명
  • 내 코드의 결과가 점검과 다를 때, 원인에 대한 힌트만 요청(코드는 요청하지 않음)
조건부 허용
  • 내가 완성한 구현의 엣지 케이스 브레인스토밍(빈 간선 목록, 고립 노드, 중복 간선, 방향/무방향, 없는 노드 질의)
  • 내가 쓴 함수의 동작을 검토해 달라는 요청(수정은 직접 한다)
  • 내 코드의 개선 아이디어 제안 요청(제안만 참고하고 코드는 직접 다시 작성)
  • 내가 쓴 구현의 시간·공간 복잡도 검토 요청(복잡도는 내가 먼저 쓴 뒤 검토만 받는다)
금지 — 적발 시 계획서의 위반 처리방안 적용
  • 과제 문장을 그대로 입력해 전체 코드 생성
  • AI가 쓴 build_graph, neighbors를 그대로, 또는 변수명만 바꿔 제출
  • 두 표현 중 무엇을 쓸지, 어떻게 만들지 등 설계 판단을 AI가 대신 내림
  • 복잡도 분석이나 구현 계획을 AI에게 대신 세우게 하여 제출
