이론 정리 · 배경 지식

이번 주 성취기준은 [12자구04-02]이다. 정렬된 데이터에서 bisect 모듈로 Lower/Upper Bound를 적용해 고속 탐색을 수행한다. 이 상자는 활동에 필요한 낱말·문법·표기만 정리한다. 탐구로 알아낼 내용은 활동 뒤의 초록색 확인 상자와 마지막 학습지(3부) 끝의 정리 상자에 있다.

1. 낱말

  • 탐색 · 정렬: 탐색은 원하는 값의 자리를 찾거나 없음을 확인하는 일이고, 정렬은 값의 크기 순서(오름차순은 작은 것부터)로 줄 세우는 일이다. 같은 값이 여러 개 있어도 된다. 예: [3, 8, 8, 15, 21].
  • 인덱스: 원소의 자리 번호이다. 맨 앞이 0번이고, 길이가 N이면 마지막은 N-1번이다.
  • 비교 1회: 목표 값과 후보 하나를 견주어 같은지, 큰지, 작은지 알아보는 일 한 번이다. 알고리즘의 빠르기는 이 횟수로 가늠한다.
  • 분할 정복: 문제를 더 작은 같은 꼴의 문제로 나누어 풀고 결과를 합치는 방법이다. 재귀(8주차)로 쓰는 경우가 많다.
  • 병합(merge): 이미 정렬된 두 리스트의 맨 앞끼리 견주어 작은 것을 하나씩 꺼내 붙여 하나의 정렬된 리스트로 합치는 일이다.
  • 피벗(pivot): 나머지 원소를 “피벗보다 작은 쪽 / 큰 쪽”으로 가르는 기준이 되는 원소이다.
  • Lower Bound / Upper Bound: 정렬된 리스트에 값 x를 넣어도 정렬이 유지되는 자리의 경계이다. Lower Bound는 x 이상인 값이 처음 나오는 인덱스, Upper Bound는 x보다 큰 값이 처음 나오는 인덱스이다. 그런 값이 없으면 리스트의 길이이다.

2. 파이썬 문법과 표준 라이브러리

# 이론 정리 예: 작은 리스트로 문법 확인
a = [3, 8, 8, 15, 21]            # 오름차순, 같은 값 8이 둘
print(a.index(8))                # 1  (처음 나오는 8의 인덱스)
print(8 in a, 9 in a)            # True False  (in: 있는지)
print(sorted([5, 2, 9, 2]))      # [2, 2, 5, 9]  (정렬된 새 리스트)
print(7 // 2, 10 // 3)           # 3 3  (//: 나눗셈의 몫만 남긴다)

import bisect                    # 정렬된 리스트용 표준 라이브러리
print(bisect.bisect_left(a, 8))  # 1  (Lower Bound)
print(bisect.bisect_right(a, 8)) # 3  (Upper Bound)
  • list.sort()는 그 리스트를 제자리에서 정렬하고, sorted(리스트)는 원래 리스트를 두고 새 리스트를 돌려준다.
  • bisect_left(a, x), bisect_right(a, x)는 정렬된 리스트 a에서 각각 Lower Bound, Upper Bound 인덱스를 돌려준다. 값을 바꾸거나 넣지는 않는다.
  • 함수는 def 이름(매개변수):로 정의하고 return으로 값을 돌려준다. 재귀는 함수가 자기 자신을 부르는 것이다.

3. 복잡도 표기 읽는 법

  • N은 입력 원소 수이다. O( )는 N이 커질 때 비용이 대략 어떤 모양으로 늘어나는지 나타낸다. 상수배와 작은 항은 무시한다. 예: 3N + 5는 O(N)이다. O(N)은 N에 비례해 늘고, O(N²)은 N이 10배가 되면 100배가 된다.
  • log₂ N은 “2를 몇 번 곱해야 N이 되는가”이다. 예: 2³ = 8이므로 log₂ 8 = 3이다. 표기에서 밑 2는 보통 생략하고 O(log N)으로 쓴다. O(N log N)은 N에 log N을 곱한 모양이다.
  • 최악의 경우는 운이 가장 나쁜 입력에서의 비용이고, 평균은 보통의 입력에서의 비용이다. 같은 알고리즘도 둘이 다를 수 있다.

지난주 BFS는 “가까운 곳부터 한 겹씩” 살폈다. 이번 주는 “가운데부터 절반씩” 줄여 갈 수 있는지 살핀다. 1차시(A1~A6)에는 손으로 탐색과 정렬을 따라 해 보자.

A1 · 몇 번 만에 찾을까1차시 · 6분 · 개인

정렬된 데이터에서 원하는 값을 몇 번 만에 찾을 수 있을까? 작은 숫자 맞히기로 시작해 보자.

숫자 맞히기 보기

컴퓨터가 1~8 중 수 하나를 정했다. 내가 수를 말하면 정답이 더 큰지 작은지만 알려 준다.

정답이 6일 때
말한 수   컴퓨터의 답
  4       더 크다
  7       더 작다
  6       맞다

4를 말해서 ‘더 크다’를 들었다. 정답이 될 수 있는 수는?

5~8이다. 말한 4와 그보다 작은 수는 후보에서 빠진다.

이어서 7을 말해 ‘더 작다’를 들었다. 남은 후보는?

5와 6이다. 말할 때마다 후보가 줄었다. 8개에서 2개가 되었다.

1~100에서는 몇 번?

같은 놀이를 1~100으로 해 보자. 가장 운이 나쁜 경우에도 반드시 맞히려면 수를 최대 몇 번 말해야 할까? 맞히는 마지막 말도 1번으로 센다. 최대 횟수와 수를 고르는 방법을 쓴다.

사전에서 찾기

가나다 순으로 실린 국어사전에서 ‘탐구’를 찾는다. 처음에 어디를 펴는지, 펼친 쪽이 ‘탐구’보다 뒤였다면 다음에 어느 쪽을 펴는지 쓴다.

10억 개에서는?

값이 작은 것부터 놓인 학번 10억 개에서 한 학번을 찾는다. 하나씩 보면 최대 몇 번일까? 내가 생각한 방법이면 몇 번쯤일까? 자릿수만 맞으면 된다.

3하나씩 보면 최대 번, 지금 생각한 방법으로 하면 번쯤

내 규칙 쓰기

세 사례에 모두 쓸 수 있는 찾는 규칙을 한 가지 쓴다. 처음에 무엇을 하고, 그다음 어떻게 하는지 순서대로 쓰자.

여기까지 세 사례에서 찾는 방법과 횟수를 어림해 보았다. A2에서는 이 규칙을 정확히 약속하고 손으로 따라 해 본다.

활동을 마친 뒤 열어 확인한다 · 세 사례의 어림값과 공통점
  • 사전: 가운데쯤을 펴 본 뒤, 목표가 앞쪽이면 앞쪽 절반만, 뒤쪽이면 뒤쪽 절반만 다시 편다.
  • 숫자 맞히기: 50을 부르고, “높다/낮다”에 따라 남은 후보의 가운데를 부르면 최악에도 7번이면 맞힌다(27 = 128 ≥ 100).
  • 학번 10억 개: 하나씩 보면 최대 10억 번이다. 한 번 견줄 때마다 후보를 절반쯤 버리면 30번 안팎이다(230 ≈ 10.7억).
  • 세 사례의 공통점은 한 번 견줄 때마다 후보를 크게 줄인다는 것이다. 내 규칙이 이와 달라도 괜찮다. A2에서 규칙을 정확히 약속하고 손으로 따라 해 본다.

작은 배열에서 규칙 보기

아직 답이 있을 수 있는 구간을 [lo, hi]로 쓴다.

규칙  ① 처음에는 lo = 0, hi = 마지막 인덱스.
      ② mid = (lo + hi) // 2 (// 는 몫만 남김)의 값 a[mid]와 목표를 견준다(비교 1회).
      ③ 같으면 끝. 크면 lo = mid + 1, 작으면 hi = mid - 1.
      ④ lo > hi 가 되면 ‘없음’으로 끝낸다.

a = [3, 7, 9, 14, 20]     인덱스 0 1 2 3 4     목표 14
단계  lo  hi  mid  a[mid]  판정
 1     0   4    2     9    14 > 9 → lo 이동, lo = 3

2단계의 mid는 몇 번 칸일까? (lo = 3, hi = 4)

(3 + 4) // 2 = 3이다. a[3] = 14라서 같음이고, 비교 2회에 끝난다.

같은 배열에서 목표가 3이면 1단계 판정은?

3 < 9이므로 mid와 그 오른쪽을 버린다. hi = mid - 1 = 1이 된다.

왜 그런지 견주기

표를 보며 답해 보자.

a[mid]가 23보다 작았을 때 mid와 그 왼쪽을 버린다. 왼쪽을 더 볼 필요가 없는 이유는?

40이 없다고 결론 내리는 때는 언제인가?

후보가 한 번 비교할 때마다 절반으로 줄어든다고 하자. 1000개를 1개가 남을 때까지 줄여 쓰고(1000 → 500 → …), 마지막 1개를 견주는 1회를 더해 센다. 1000개와 100만 개일 때 규칙의 최대 비교 횟수는 몇 번쯤일까? 하나씩 견주면 같은 경우 몇 번일까?

여기까지 후보 범위를 가운데에서 줄이는 규칙으로 23과 40을 찾았다. A3에서는 같은 규칙을 다른 배열에 써 본다.

  • 질문 2: 후보 범위가 비었을 때(lo > hi), 즉 마지막으로 38과 견준 직후에 알게 된다.

5는 제대로 찾았다. 그렇다면 UNS에서 이 규칙을 믿어도 될까?

5는 경로가 우연히 5가 놓인 칸을 지났을 뿐이다. 23과 56은 놓쳤다.

놓친 까닭 견주기

23은 UNS에 있는데 규칙은 “없음”이라 했다. 추적표를 보며 어느 단계에서부터 어긋났는지 찾고, 원인 후보를 서로 다르게 2가지 쓰자. 후보는 결론이 아니라 ‘그럴 수 있다’는 짐작이다.

여기까지 같은 규칙이 UNS에서는 23과 56을 놓쳤다. A4에서는 8개를 줄 세우는 두 방식을 손으로 따라 해 본다.

네 개로 두 방식 보기

[6, 2, 7, 1]을 오름차순으로 줄 세운다. 방식 가는 쪼갠 뒤 합치고, 방식 나는 기준 원소(피벗)로 가른다.

방식 가  1번 [6] + [2] → [2, 6]            비교 1회
        2번 [7] + [1] → [1, 7]            비교 1회
        3번 [2, 6] + [1, 7] → [1, 2, 6, 7]  비교 3회
방식 나  1번 [6, 2, 7, 1] 피벗 6 → 작은 쪽 [2, 1], 큰 쪽 [7]  비교 3회
        2번 [2, 1] 피벗 2 → 작은 쪽 [1], 큰 쪽 [ ]          비교 1회

x < 피벗이면 작은 쪽, 아니면 큰 쪽이다. 비교는 가를 대상 길이 - 1회이다.

[5, 3, 4]를 방식 나로 처음 가르면(피벗 5) 비교는 몇 회일까?

2회이다. 3과 4를 각각 5와 견준다.

방식 가는 합칠 때 두 리스트의 맨 앞끼리 견준다. 한쪽이 바닥나면 남은 것은 비교 없이 붙인다. 위 3번은 2·1, 2·7, 6·7을 견주고 7을 붙였다.

[1, 4]와 [2, 3]을 합칠 때 비교는 몇 회일까?

3회이다. 1·2, 4·2, 4·3을 견주고 남은 4를 붙인다.

A5 · 입력이 이미 줄 서 있다면1차시 · 11분 · 개인

이미 줄 서 있는 입력에서는 두 방식이 어떻게 달라질까? 비교 횟수와 깊이를 세어 보자.

깊이 세는 법 보기

깊이는 재귀 호출이 겹쳐 들어간 가장 깊은 단계의 수이다. 처음 호출이 1단계이고, 길이 0 또는 1에서 멈추는 호출도 한 단계로 센다. 가운데 피벗은 a[len(a)//2]이다. 가운데 피벗으로 해도 이 예는 비교 합 3회, 깊이 3이다.

[3, 1, 2]  첫 원소 피벗 3 → 작은 쪽 [1, 2], 큰 쪽 [ ]   비교 2회
          [1, 2]는 피벗 1 → [ ]와 [2]               비교 1회
          비교 합 3회, 깊이 3
          가운데 피벗이면 a[1] = 1 → 작은 쪽 [ ], 큰 쪽 [3, 2]  (이어서 비교 합 3회, 깊이 3)

[4, 5]를 첫 원소 피벗으로 가르면 깊이는?

[4, 5]가 1단계, 갈라진 [ ]와 [5]가 2단계이다.

방식 가로 4개를 합칠 때 합치는 층은 몇 층일까? (1개씩 → 2개씩 → 4개로)

1개씩 → 2개씩 → 4개로, 합치는 층은 두 층이다.
