사용법#how

  1. 코드는 각 활동의 “내 코드” 칸(편집기)에 쓰고 [▶ 실행](또는 Ctrl/⌘+Enter)으로 확인한다. 골격과 예시는 [예시 코드] 단추에서 [복사]하거나 [편집기에 추가]로 가져온다(편집기의 맨 아래에 이어 붙는다).

  3. 다른 쪽 코드가 필요하면 앞 쪽의 편집기에서 실행해 성공시킨 뒤, 이 쪽에서 [앞 쪽 코드 불러오기]를 누른다. 이 단추는 이 브라우저에서 앞 쪽에 성공한 실행 기록(8시간 안)을 쓰며, 파이썬 환경에만 정의를 가져오고 편집기 칸에는 코드를 넣지 않는다. 기록이 없다는 안내가 나오면 앞 쪽 편집기의 코드를 복사해 이 쪽 편집기 맨 위에 붙여 넣고 실행한다.
  4. NameError는 아직 정의하지 않은 이름을 쓴 것이다. 앞 코드를 실행했는지, [앞 쪽 코드 불러오기]를 눌렀는지 확인한다.

  6. 편집기에 쓴 코드는 [저장(JSON)] 때 함께 저장·제출된다. 파이썬 파일(.py)은 따로 만들지 않는다.

예측 후 측정 (SORTBIG)

활동지 3부 A11 표의 예측 칸을 먼저 채운 뒤 실행한다. 입력은 시드 12로 고정해 만들므로 같은 코드를 실행하면 같은 값이 나온다. 마지막 입력(정렬된 2000개)에서 무슨 일이 일어나는지도 먼저 예측한다. 퀵 칸에 숫자 대신 오류 이름이 나오면 그 이름을 그대로 활동지에 쓴다. 예측 칸이 비어 있으면 [예시 코드]의 이 코드를 실행하지 않는다.

# SORTBIG: 시드를 12로 고정한 입력. 예측을 활동지에 먼저 적고 실행한다.
import random, sys
# 재귀가 너무 깊어지면 RecursionError가 나도록 한계를 1000으로 정해 둔다
sys.setrecursionlimit(1000)
random.seed(12)

# 0부터 n-1까지를 무작위로 섞은 리스트를 만든다
def shuffled(n):
    r = list(range(n))  # 0, 1, ..., n-1 리스트
    random.shuffle(r)  # r을 제자리에서 섞는다
    return r

# 병합 정렬과 퀵 정렬을 실행하고 각 비교 횟수를 돌려준다
def counts(a):
    c1, c2 = [0], [0]
    merge_sort(a, c1)
    try:
        quick_sort(a, c2)
        q = c2[0]
    except Exception as e:
        q = type(e).__name__
    return c1[0], q

# (이름, 입력) 쌍을 차례로 꺼내 비교 횟수를 출력한다
for name, a in (("섞은 200", shuffled(200)), ("섞은 500", shuffled(500)), ("섞은 1000", shuffled(1000)),
                ("정렬된 200", list(range(200))), ("정렬된 500", list(range(500))), ("정렬된 2000", list(range(2000)))):
    m, q = counts(a)
    print(name, "병합:", m, " 퀵(첫 원소 피벗):", q)

  • 위 점검 코드에서 sorted(a)는 내 정렬이 맞는지 비교하는 기준으로 쓰였다.

학습 내용 · 점검 읽는 법과 과제 요건, 복잡도 서술 쓰는 법
  • 순서: ① 세 함수를 한 칸에 모아 실행한다. ② TA를 실행한다. ③ 값 점검, 이어서 큰 입력 속도 점검을 실행한다. ④ closest_value 점검을 실행한다. AssertionError가 나오면 메시지의 입력과 두 값을 보고 손으로 따라가 본다.
  • 요건 확인: 입력 불변은 호출 전후에 TA가 같은지 점검 코드가 검사한다. 큰 입력은 100만 개 리스트에 질의 10만 번을 약 1초 안쪽(기기에 따라 다르며 상대 판단)에 끝내는지 본다. 5초가 넘으면 중단 메시지가 나온다. bisect 사용은 세 함수가 모두 경계 함수로 계산하는지를 말한다.
  • 복잡도 서술 쓰는 법(내 답을 쓴다): ① 입력 크기 N과 함수 한 번 부를 때 하는 일(경계 함수를 몇 번 부르는가, 그 한 번에 몇 번쯤 견주는가)을 쓴다. ② 시간 복잡도와 그 근거, 공간 복잡도(새 리스트를 만드는가)와 근거를 쓴다. ③ 하나씩 세는 방법과 비교해 한 줄 덧붙인다.

과제 요건(과제 안내 후반부)

  • 세 함수는 bisect 모듈을 써서 O(log N)으로 구한다. list.count나 모든 원소를 훑는 반복문으로 푼 풀이는 아래 큰 입력 점검을 통과하지 못한다.
  • 입력 리스트를 바꾸지 않고, 다시 정렬하지도 않는다. 같은 입력으로 두 번 불러도 같은 값을 돌려준다.
  • 입력은 정렬된(오름차순) 리스트로 주어진다. 정렬되지 않은 입력은 과제 범위가 아니다.

# random은 무작위 값, time은 걸린 시간을 다루는 모듈이다
import random, time

# 정의대로 하나씩 세는 느린 기준 함수이다(정답 확인용)
def brute_equal(a, x):
    return sum(1 for v in a if v == x)

def brute_range(a, lo, hi):
    return sum(1 for v in a if lo <= v <= hi)

# 여러 입력(빈 리스트, 같은 값만 있는 리스트 포함)으로 점검한다

        # 내 함수와 느린 기준의 값이 다르면 메시지를 보이며 멈춘다
        assert count_equal(a, x) == brute_equal(a, x), "count_equal(%r, %d)가 다르다" % (a, x)
    for lo in range(-5, 30, 3):
        for hi in range(-5, 30, 4):

(가-2) closest_value 점검

closest_value를 위 내 코드 칸에 쓰고 실행한 뒤, 아래 점검으로 확인한다. 점검은 내 결과가 “정의를 만족하는지”를 검사한다. 정답 함수는 제공하지 않는다. 먼저 활동지 2부 A9의 closest 질문 칸에 DUP에서 가장 가까운 값을 눈으로 찾아 쓴 내용을 떠올린다.

# A14 점검 (가-2): closest_value의 결과가 정의를 만족하는지 검사한다.
def check_closest(a, x, r):
    # 정의: 거리가 가장 작고, 거리가 같으면 작은 값이 답이다. 빈 리스트는 None
    if not a:
        assert r is None, "빈 리스트에서는 None이어야 한다"
        return
    assert r in a, "closest_value(%r, %d)가 리스트에 없는 값 %r을 돌려주었다" % (a, x, r)
    for v in a:
        assert (abs(r - x), r) <= (abs(v - x), v), "closest_value(%r, %d)=%r보다 %r이 더 가깝거나 동률에서 더 작다" % (a, x, r, v)

# 여러 입력(빈 리스트, 같은 값만 있는 리스트 포함)으로 점검한다
for a in (TA, [], [9], [4, 4, 4]):
    before = list(a)  # 복사본을 저장해 두고 나중에 비교한다
    for x in range(-5, 100, 3):
        check_closest(a, x, closest_value(a, x))
    assert a == before, "입력 리스트가 바뀌었다"
print("A14 closest_value 값 점검 통과")

    print("closest_value 큰 입력 점검 끝: %.2f초 (대략 1초 안쪽이면 충분히 빠른 편이다)" % (time.perf_counter() - t0))

# ROPE 점검: 1부터 하나씩 늘려 가며 찾은 느린 답과 비교하고, count_pieces를 몇 번 불렀는지 센다.
_real = count_pieces  # 원래 함수를 따로 보관한다
calls = [0]  # 호출 횟수를 세는 칸
# 같은 이름으로 다시 정의해 호출될 때마다 횟수를 1 올린다
def count_pieces(ropes, L):
    calls[0] += 1
    return _real(ropes, L)

mine = max_piece_length(ropes, k)  # 내 함수로 답을 구한다
n_calls = calls[0]  # 호출 횟수를 저장한다
count_pieces = _real  # 원래 함수로 되돌린다

slow = max(L for L in range(1, max(ropes) + 1) if count_pieces(ropes, L) >= k)
