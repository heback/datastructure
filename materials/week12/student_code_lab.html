A7 · 처음으로 x 이상이 나오는 자리 찾기14분 · 개인(옆 학생과 대조)

약속 · 표기와 질문 바꾸기
  • A2에서는 후보 범위를 닫힌 구간 [lo, hi]로 썼다. 코드에서는 후보 범위 [lo, hi)(hi는 포함하지 않는다)로 쓴다. 처음에는 전체, 즉 lo = 0, hi = len(a)로 시작한다. 두 표기는 “끝 인덱스 + 1 = hi”로 대응한다.
  • “목표가 있는가?” 대신 “처음으로 x 이상이 나오는 자리는 어디인가?”를 묻는다. 이 자리를 lower bound라고 한다. 처음으로 x 초과가 나오는 자리는 upper bound이다. 두 값은 모두 인덱스이다.
  • 이 시점까지 bisect 모듈은 쓰지 않는다. 직접 구현한 뒤 다음 활동에서 비교한다. 입력 리스트는 오름차순(같은 값이 여럿 있을 수 있음)으로 주어진다고 가정한다.

아래 골격에서 lower_bound를 완성하고, upper_bound는 한 곳(⑦)만 채운다. 완성한 뒤 DUP에서 값을 먼저 예측하고(활동지 2부 A7 칸), 예측 코드를 실행해 확인한다.

입력과 골격

# A7 입력
DUP = [1, 3, 3, 3, 5, 7, 7, 9, 12, 12, 12, 12, 15]
SORTED = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
def lower_bound(a, x):               # 처음으로 x 이상인 자리
    lo, hi = ____1____, ____2____       # ①② 후보 범위 [lo, hi)
    while ____3____:                    # ③
        mid = (lo + hi) // 2
        if ____4____:                   # ④ a[mid]가 x보다 작다
            lo = ____5____              # ⑤
        else:
            hi = ____6____              # ⑥
    return lo

def upper_bound(a, x):               # 처음으로 x 초과인 자리. lower_bound에서 한 곳만 다르다
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if ____7____:                   # ⑦
            lo = mid + 1
        else:
            hi = mid
    return lo

Tab 키는 4칸 들여쓰기이다. 다음 칸으로 이동하려면 Esc를 누른 뒤 Tab을 누른다.

예측 후 실행

# 예측을 활동지에 먼저 적은 뒤 실행한다.
for x in (12, 4, 20):
    print("x =", x, " lower_bound:", lower_bound(DUP, x), " upper_bound:", upper_bound(DUP, x))

점검

# A7 점검: 정의를 그대로 옮긴 느린 방법(처음부터 훑기)과 내 결과를 비교한다.
import signal

def first_ge(a, x):                  # 처음으로 x 이상인 원소의 자리(없으면 len(a))
    for i, v in enumerate(a):
        if v >= x:
            return i
    return len(a)

def first_gt(a, x):                  # 처음으로 x 초과인 원소의 자리(없으면 len(a))
    for i, v in enumerate(a):
        if v > x:
            return i
    return len(a)

def _timeout(signum, frame):
    raise TimeoutError("3초 안에 끝나지 않았다. 반복이 끝나지 않는 것은 아닌지 lo, hi의 변화를 확인한다")

if hasattr(signal, "SIGALRM"):
    signal.signal(signal.SIGALRM, _timeout)
    signal.alarm(3)

for name, a in (("DUP", DUP), ("SORTED", SORTED), ("빈 리스트", []), ("원소 1개", [7])):
    for x in range(-2, 100):
        got_l, got_u = lower_bound(a, x), upper_bound(a, x)
        assert got_l == first_ge(a, x), "%s에서 lower_bound(%d)=%r 인데 정의대로 찾으면 %r이다" % (name, x, got_l, first_ge(a, x))
        assert got_u == first_gt(a, x), "%s에서 upper_bound(%d)=%r 인데 정의대로 찾으면 %r이다" % (name, x, got_u, first_gt(a, x))
if hasattr(signal, "SIGALRM"):
    signal.alarm(0)
print("A7 점검 통과")

점검이 통과하면 활동지 2부에 예측과 실제 값을 쓴다. 다음 활동(A8)에서 이 두 함수를 다시 쓰므로 완성한 코드를 파일에 보관해 둔다. 결과가 다르게 나오면 오류 메시지의 입력 값으로 lo, hi, mid를 손으로 따라가 본다.

실습 과제 안내 · 정렬된 리스트에서 개수와 가장 가까운 값 구하기A7 착수 · A9 이어짐 · A14 마무리 · 잔여는 주간 과제

과제 (함수 3개)
  • count_equal(a, x): 리스트 a에서 x와 같은 원소의 개수를 돌려준다.
  • count_in_range(a, lo, hi): 닫힌 구간 [lo, hi](양끝 포함)에 들어 있는 원소의 개수를 돌려준다. lo > hi이면 0이다.
  • closest_value(a, x): x와 가장 가까운 원소를 돌려준다. 거리가 같으면 작은 값, 빈 리스트이면 None이다.
  • 입력 a는 정렬된(오름차순, 같은 값이 여럿일 수 있는) 리스트로 주어진다.
  • A7에서 착수하고, A9(2차시)에서 앞의 두 함수를 이어 쓰며, A14(3차시)에서 세 함수를 마무리 점검한다. A14의 밧줄 자르기는 채점하지 않는 보조 연습이다. 미완 부분은 주간 과제로 이어진다.

AI 활용 3단계 · 이 과제에 맞춘 예허용 · 조건부 허용 · 금지

기준은 “AI에게 무엇을 시켰는가”이다. 개념·문법·오류 원인을 묻는 것은 허용이고, 과제 요구사항이나 완성된 구현 자체를 입력해 결과물(코드·글)을 받아 제출하는 것은 금지이다.

허용 — 성찰일지에 간단히 기록
  • “이진 탐색이란 무엇이야?”, “lower bound와 upper bound는 뭐가 달라?” 같은 개념·문법 질의

  • “lower bound라는 말은 어디서 유래했어?” 같은 용어·설계 배경 설명(코드는 받지 않음)
  • 내 코드 결과가 점검 테스트와 다를 때 원인 힌트만 요청
조건부 허용 — 출처와 반영 여부를 성찰일지에 반드시 기록
  • 완성한 구현의 엣지 케이스 브레인스토밍(빈 리스트, 원소 1개, 모두 같은 값, 목표가 전체보다 작거나 큼, lo>hi, 같은 값이 여러 개)
  • 내가 쓴 코드가 입력 리스트를 바꾸는지, 두 번 호출해도 같은 값인지, 큰 입력에서 느리지 않은지 검토해 달라는 요청(수정은 직접 한다)
  • 내 코드의 개선 아이디어 제안 요청(제안만 참고하고 코드는 직접 다시 작성)
  • 기록 예: “AI가 빈 리스트 케이스를 제안 → 채택/미채택, 이유”
금지 — 적발 시 계획서의 위반 처리방안 적용
  • 과제 문장(“정렬된 리스트에서 값의 개수, 구간 개수, 가장 가까운 값을 구하는 함수를 작성하라”)을 그대로 입력해 전체 코드 생성
  • AI가 쓴 count_in_range/closest_value를 그대로, 또는 변수명만 바꿔 제출
  • 경계를 포함할지 여부, 어느 경계를 쓸지, 동률일 때 어느 값을 고를지 등 설계 판단을 AI가 대신 내림
  • 복잡도 분석이나 구현 계획을 AI가 대신 세우게 하여 제출
  • 성찰일지 AI 대필
