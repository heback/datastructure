12주차 실습 코드 1부 — 후보 범위 [lo, hi)로 경계 찾기

성취기준 [12자구04-02] 중 이 주차의 범위: 정렬된 데이터에서 Lower/Upper Bound를 이용한 고속 탐색을 코드로 구현한다. 이 파일은 2차시 시작(A7)에 사용한다. 이 파일의 빈칸을 채우고 점검이 통과할 때까지 고친다.

학번·이름은 위쪽 저장 바에 쓴다.

#사용법#A7#실습과제#AI활용목록

사용법#how

  1. 코드는 각 활동의 “내 코드” 칸(편집기)에 쓴다. 골격과 예시는 편집기의 [예시 코드] 단추를 눌러 [복사]하거나 [편집기에 추가]로 가져온다. [편집기에 추가]는 편집기의 맨 아래에 이어 붙는다.
  2. 실행은 편집기의 [▶ 실행](또는 Ctrl/⌘+Enter)이다. 같은 쪽(페이지)의 편집기들은 파이썬 환경을 공유하므로, 앞 편집기에서 실행한 함수와 변수를 뒤 편집기에서 쓴다. 쪽을 옮기면 환경이 비므로, 다른 쪽 코드가 필요하면 앞 쪽의 편집기에서 실행해 성공시킨 뒤 새 쪽에서 [앞 쪽 코드 불러오기]를 누른다. 이 단추는 이 브라우저에서 앞 쪽에 성공한 실행 기록(8시간 안)을 쓰며, 파이썬 환경에만 정의를 가져오고 편집기 칸에는 코드를 넣지 않는다. 기록이 없다는 안내가 나오면 앞 쪽 편집기의 코드를 복사해 이 쪽 편집기 맨 위에 붙여 넣고 실행한다.
  3. 골격의 ____1____ 같은 자리가 채울 곳이다. 번호는 주석의 ①~⑦과 같다. 채우지 않고 실행하면 SyntaxError나 NameError가 나는데, 아직 채울 곳이 남아 있거나 아직 정의하지 않은 이름을 썼다는 뜻이다.
  4. 점검이 실패하면 AssertionError와 메시지가 나온다. 메시지의 입력 값으로 lo, hi, mid를 손으로 따라가 본다.
  5. 정답과 기대 값은 이 파일에 없다. 점검은 정의대로 처음부터 훑어 구한 값과 내 결과를 비교한다.
  6. 실행은 15초를 넘기면 멈추고 환경이 초기화된다. 무한 반복이 없는지 확인한다.
  7. 편집기에 쓴 코드는 [저장(JSON)] 때 함께 저장·제출된다. 파이썬 파일(.py)은 따로 만들지 않는다.

약속 · 표기와 질문 바꾸기
  • A2에서는 후보 범위를 닫힌 구간 [lo, hi]로 썼다. 코드에서는 후보 범위 [lo, hi)(hi는 포함하지 않는다)로 쓴다. 처음에는 전체, 즉 lo = 0, hi = len(a)로 시작한다. 두 표기는 “끝 인덱스 + 1 = hi”로 대응한다.
  • “목표가 있는가?” 대신 “처음으로 x 이상이 나오는 자리는 어디인가?”를 묻는다. 이 자리를 lower bound라고 한다. 처음으로 x 초과가 나오는 자리는 upper bound이다. 두 값은 모두 인덱스이다.
  • 이 시점까지 bisect 모듈은 쓰지 않는다. 직접 구현한 뒤 다음 활동에서 비교한다. 입력 리스트는 오름차순(같은 값이 여럿 있을 수 있음)으로 주어진다고 가정한다.

먼저 활동지 2부 A7의 “코드를 쓰기 전에” 칸에 a[mid]와 x의 크기에 따라 lower bound의 위치를 쓰고, 같은 쪽 표에 DUP의 lower bound와 upper bound를 눈으로 보고 예측해 적는다(앞에서 정한 약속의 정의만 쓴다). 예측 칸이 비어 있으면 [예시 코드]의 예측 확인 코드를 실행하지 않는다.

실행 순서 ① [예시 코드]에서 [제공 코드]와 [뼈대]를 이 순서로 편집기에 추가하고 빈칸을 채워 [▶ 실행]한다. ② [테스트] 점검을 맨 아래에 추가해 실행한다. ③ 점검이 통과한 뒤 [예시] 예측 후 실행을 추가해 실제 값을 확인하고, 예측과 다른 칸이 있으면 이유를 써 둔다.

학습 내용 · 후보 범위 [lo, hi)와 lower/upper bound
A2 (닫힌 구간)오늘 (반열린 구간)
후보 범위[lo, hi][lo, hi) (hi는 포함하지 않음)
시작hi = len(a) - 1hi = len(a)
계속 조건lo <= hilo < hi

위 약속의 정의를 작은 예 B로 본다(B는 DUP와 다른 리스트이다).

B = [2, 4, 4, 6, 9]      인덱스 0  1  2  3  4
x = 4 :  2 | 4  4 | 6  9      lower bound = 1 (처음 x 이상), upper bound = 3 (처음 x 초과)
x = 6 :  2  4  4 | 6 | 9      lower bound = 3,               upper bound = 4
세로선은 칸과 칸 사이의 경계이다. 두 값은 모두 인덱스이다.
  • lower bound는 bisect_left와, upper bound는 bisect_right와 같은 말이다(A8에서 확인한다).
  • 빈칸을 채우는 순서: 먼저 ④ “a[mid]가 어느 쪽 값이면 답이 mid의 오른쪽에 있다고 말할 수 있는가”를 말로 정한 뒤, ⑤⑥에서 후보 범위가 어떻게 줄어야 하는지 정한다. upper_bound는 lower_bound에서 어느 부분이 달라져야 하는지 옆 학생에게 말해 본다.

입력(DUP, SORTED)

# A7 입력
# DUP: 같은 값이 여러 번 나오는 정렬된 리스트이다
DUP = [1, 3, 3, 3, 5, 7, 7, 9, 12, 12, 12, 12, 15]
# SORTED: 같은 값이 없는 정렬된 리스트이다
SORTED = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]

골격(lower_bound, upper_bound)

# def: 함수를 정의한다. a는 정렬된 리스트, x는 찾는 값이다
def lower_bound(a, x):               # 처음으로 x 이상인 자리
    lo, hi = ____1____, ____2____       # ①② 후보 범위 [lo, hi)
    while ____3____:                    # ③
        mid = (lo + hi) // 2  # // 는 나눗셈의 몫(정수)이다
        if ____4____:                   # ④ lower bound의 정의에서, a[mid]가 어느 쪽 값이면 답이 mid의 오른쪽에 있다고 말할 수 있는 조건
            lo = ____5____              # ⑤
        else:
            hi = ____6____              # ⑥
    return lo  # 함수를 끝내며 lo를 돌려준다

# lower_bound와 같은 뼈대의 함수이다. 빈칸은 ⑦ 하나이다.
# upper bound의 정의(처음으로 x 초과)를 쓰려면 어느 부분이 달라져야 하는지 먼저 옆 학생에게 말로 설명한 뒤 채운다
def upper_bound(a, x):               # 처음으로 x 초과인 자리를 돌려준다
    lo, hi = 0, len(a)
    while lo < hi:  # lo가 hi보다 작은 동안 반복한다
        mid = (lo + hi) // 2
        if ____7____:                   # ⑦
            lo = mid + 1
        else:
            hi = mid
    return lo

점검

# A7 점검: 정의를 그대로 옮긴 느린 방법(처음부터 훑기)과 내 결과를 비교한다.
# 내 코드 칸에서 lower_bound, upper_bound를 먼저 실행해 둔 뒤 실행한다.

# 정의 그대로 앞에서부터 하나씩 보는 느린 기준 함수이다
def first_ge(a, x):                  # 처음으로 x 이상인 원소의 자리(없으면 len(a))
    for i, v in enumerate(a):  # enumerate: 자리 i와 값 v를 함께 꺼낸다
        if v >= x:
            return i
    return len(a)

def first_gt(a, x):                  # 처음으로 x 초과인 원소의 자리(없으면 len(a))
    for i, v in enumerate(a):
        if v > x:
            return i
    return len(a)

# 여러 입력(빈 리스트, 원소 1개 포함)을 차례로 점검한다
for name, a in (("DUP", DUP), ("SORTED", SORTED), ("빈 리스트", []), ("원소 1개", [7])):
    for x in range(-2, 100):  # x를 -2부터 99까지 바꿔 본다
        # 내가 만든 두 함수를 호출해 결과를 받는다
        got_l, got_u = lower_bound(a, x), upper_bound(a, x)
        # assert 조건, 메시지: 조건이 거짓이면 메시지를 보이며 멈춘다. 즉 내 함수가 정의와 다른 값을 낸 것이다
        assert got_l == first_ge(a, x), "%s에서 lower_bound(%d)=%r 인데 정의대로 찾으면 %r이다" % (name, x, got_l, first_ge(a, x))
        assert got_u == first_gt(a, x), "%s에서 upper_bound(%d)=%r 인데 정의대로 찾으면 %r이다" % (name, x, got_u, first_gt(a, x))
# 위의 assert를 모두 통과해야 이 줄이 실행된다
print("A7 점검 통과")

과제 (함수 3개)
  • count_equal(a, x): 리스트 a에서 x와 같은 원소의 개수를 돌려준다.
  • count_in_range(a, lo, hi): 닫힌 구간 [lo, hi](양끝 포함)에 들어 있는 원소의 개수를 돌려준다. lo > hi이면 0이다.
  • closest_value(a, x): x와 가장 가까운 원소를 돌려준다. 거리가 같으면 작은 값, 빈 리스트이면 None이다.
  • 입력 a는 정렬된(오름차순, 같은 값이 여럿일 수 있는) 리스트로 주어진다.
  • A7에서 착수하고, A9(2차시)에서 앞의 두 함수를 이어 쓰며, A14(3차시)에서 세 함수를 마무리 점검한다. A14의 밧줄 자르기는 채점하지 않는 보조 연습이다. 미완 부분은 주간 과제로 이어진다.

AI 활용 3단계 · 이 과제에 맞춘 예허용 · 조건부 허용 · 금지

기준은 “AI에게 무엇을 시켰는가”이다. 개념·문법·오류 원인을 묻는 것은 허용이고, 과제 요구사항이나 완성된 구현 자체를 입력해 결과물(코드·글)을 받아 제출하는 것은 금지이다.

허용 — 성찰일지에 간단히 기록
  • “이진 탐색이란 무엇이야?”, “lower bound와 upper bound는 뭐가 달라?” 같은 개념·문법 질의
  • “TypeError: '<' not supported between instances of 'int' and 'str'가 무슨 뜻이야?”, “IndexError: list index out of range가 왜 나오는지 해설” 같은 오류 메시지 해설
  • “lower bound라는 말은 어디서 유래했어?” 같은 용어·설계 배경 설명(코드는 받지 않음), 용어 번역·개념 요약, 수업 자료 복습 질문
  • 내 코드 결과가 점검 테스트와 다를 때 원인 힌트만 요청
조건부 허용 — 출처와 반영 여부를 성찰일지에 반드시 기록
  • 완성한 구현의 엣지 케이스 브레인스토밍(빈 리스트, 원소 1개, 모두 같은 값, 목표가 전체보다 작거나 큼, lo>hi, 같은 값이 여러 개)
  • 내가 쓴 코드가 입력 리스트를 바꾸는지, 두 번 호출해도 같은 값인지, 큰 입력에서 느리지 않은지 검토해 달라는 요청(수정은 직접 한다)
  • 내가 작성한 구현의 복잡도가 맞는지 검토해 달라는 요청(예: “내가 쓴 복잡도 분석문과 코드를 붙여 줄 테니 분석이 코드와 맞는지 검토해줘”). 복잡도 분석 자체는 내가 먼저 쓰고 AI가 대신 쓰지 않는다
  • 내 코드의 개선 아이디어 제안 요청(제안만 참고하고 코드는 직접 다시 작성)
  • 기록 예: “AI가 빈 리스트 케이스를 제안 → 채택/미채택, 이유”
금지 — 적발 시 계획서의 위반 처리방안 적용
  • 과제 문장(“정렬된 리스트에서 값의 개수, 구간 개수, 가장 가까운 값을 구하는 함수를 작성하라”)을 그대로 입력해 전체 코드 생성
  • AI가 쓴 count_in_range/closest_value를 그대로, 또는 변수명만 바꿔 제출
  • 경계를 포함할지 여부, 어느 경계를 쓸지, 동률일 때 어느 값을 고를지 등 설계 판단을 AI가 대신 내림
  • 복잡도 분석이나 구현 계획을 AI가 대신 세우게 하여 제출
  • 성찰일지 AI 대필
