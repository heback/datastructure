9주차 탐구 활동지 — 힙(Heap)과 우선순위 큐

핵심질문은 “들어온 순서와 무관하게, 우선순위가 가장 높은 데이터를 즉시 뽑으려면 어떻게 해야 할까?”이다. 활동마다 작은 사례를 본 뒤 직접 해 보자. 확인 상자는 활동 끝에 닫혀 있으니 쓴 뒤에 연다.

제출하지 않고 스스로 학습하는 활동지이다. 쓴 내용은 이 브라우저에 자동으로 보관된다.

이론 정리 · 배경 지식예습·활동 중 참고용

별도 활동 시간은 없다. 수업 전에 읽거나 활동 중 모르는 말이 나올 때 찾아본다.

이론 정리 · 배경 지식
  • 우선순위 큐(priority queue)는 데이터를 넣을 때 우선순위(먼저 처리할 정도를 나타내는 값)를 함께 두고, 꺼낼 때는 넣은 순서가 아니라 우선순위가 가장 높은 것을 꺼내는 자료구조이다. 줄 선 순서대로 꺼내는 일반 큐(FIFO)와 꺼내는 기준이 다르다. 쓰이는 곳은 운영체제의 작업 스케줄링, 게임 이벤트 처리, 길 찾기 등이다.
  • 힙(heap)은 우선순위 큐를 구현하는 한 가지 방법이다. “우선순위 큐”는 어떤 기능인지를, “힙”은 그 기능을 어떻게 만드는지를 가리킨다.
  • 이진 트리는 각 노드의 자식이 최대 2개(왼쪽·오른쪽)인 트리이다. 위쪽 노드를 부모, 바로 아래 노드를 자식, 맨 위를 루트, 자식이 없는 노드를 리프라 한다. 트리의 높이는 루트에서 가장 먼 리프까지의 노드 수이다(8주차와 같다).
  • 완전 이진 트리는 위층부터 차례로, 같은 층에서는 왼쪽부터 빈틈없이 채운 이진 트리이다.
  • 최소 힙은 모든 부모가 자식보다 크지 않은(작거나 같은) 완전 이진 트리이다. 반대로 모든 부모가 자식보다 작지 않으면 최대 힙이다.
  • 배열(리스트)로 트리 나타내기: 노드 값을 위에서 아래로, 같은 층에서는 왼쪽에서 오른쪽으로 리스트에 차례로 담을 수 있다. 칸 번호는 0부터 센다. 칸 번호와 부모·자식 사이의 관계는 A3에서 직접 찾는다.
  • 파이썬 heapq 모듈은 리스트를 힙의 배열로 보고 다룬다. 최소 힙만 제공한다. 쓰는 법은 아래와 같고, 각 함수의 동작은 A9에서 실행하며 확인한다.
쓰는 법하는 일
heapq.heappush(h, x)힙 h에 값 x를 넣는다.
heapq.heappop(h)가장 작은 값을 빼서 돌려준다.
heapq.heapify(h)이미 있는 리스트 h를 힙으로 바꾼다.
h[0]0번 칸의 값을 읽는다.

작은 예이다. (우선순위, 이름) 튜플은 앞의 값부터 비교되므로 우선순위가 작은 것이 먼저 나온다. 숫자가 작을수록 우선순위가 높다.

import heapq

events = []
heapq.heappush(events, (3, "효과음"))
heapq.heappush(events, (1, "데미지"))
heapq.heappush(events, (2, "화면 흔들림"))
print(events[0])
while events:
    print(heapq.heappop(events))

출력은 (1, '데미지')가 한 번 나온 뒤, (1, '데미지'), (2, '화면 흔들림'), (3, '효과음')이 한 줄씩 나온다. 처음 한 줄은 events[0]을 읽기만 한 것이고, 이어지는 세 줄은 하나씩 꺼낸 것이다.

  • 시간복잡도 표기 읽는 법: 입력 크기를 N이라 할 때 작업량이 N이 커지면 어떻게 늘어나는지를 나타낸다. O(1)은 N과 무관하게 일정한 횟수, O(N)은 N에 비례, O(N2)은 N의 제곱에 비례, O(log N)은 N이 두 배가 될 때 한 단계만 늘어나는 정도이다. 예: 1024를 계속 반으로 나누면 10번 만에 1이 되므로 log2 1024 = 10이다. 이 수업에서 log는 밑이 2인 로그를 뜻한다.
  • 같은 일을 하는 두 방법의 비용은 “비교·자리바꿈을 몇 번 했는가”를 세어 비교한다. 이것은 A2에서 직접 센다.

0번 칸 3  ≤  1번 칸 5, 2번 칸 4      지켜진다
1번 칸 5  ≤  3번 칸 8, 4번 칸 6      지켜진다
2번 칸 4  자식이 없다               볼 것 없다

활동을 마친 뒤 열어 확인한다 · A8 정리: 두 방법의 기록과 비교

(가) push:
9 → [9] (0)

합계 6번, 최종 [1,3,2,4,8,7,6,9,5].

(나) 마지막 부모는 3번 칸이다(N=9). 4~8번 칸은 자식 칸 번호 2i+1이 9 이상이라 자식이 없는 리프이다.

합계 6번이고 최종 배열이 (가)와 같다. 이 입력(H0)에서만 같을 수 있다. 방향은 (가)가 위로 올리기(sift-up), (나)가 아래로 내리기(sift-down)이고, (나)에서 리프(4~8번 칸)는 아무 일도 하지 않는다.

H2 = [1, 4, 5, 3, 2]는 하나씩 push하면 [1,2,5,4,3], heapify하면 [1,2,5,3,4]로 서로 다르다. 둘 다 부모 ≤ 자식을 지키므로 올바른 힙이다. 힙은 배열이 하나로 정해지는 구조가 아니라 약속을 지키는 배열이다. 리프는 자식이 없어 이미 약속을 만족하므로 sift-down을 해도 바뀌는 것이 없다.

작은 코드 실행해 보기

heapq는 파이썬이 만들어 둔 힙이다. heappush는 값을 넣고(A6), heappop은 가장 작은 값을 빼서 돌려주며(A7), heapify는 리스트를 힙으로 바꾼다(A8). 아래 코드의 마지막 줄을 먼저 예측해 보자.

마지막 print에는 무엇이 나올까?

실행해 보니 heappop은 값을 돌려주는 것 말고 하는 일이 하나 더 있다. 무엇일까?

heappop은 루트를 빼고 힙을 다시 고친다. 그래서 새 h[0]이 다음으로 작은 값이다.

9개 값에서 예측하고 실행하기

같은 코드를 9개 값에서 실행한다. 실습 코드 A9에서 실행해 실제 칸에 옮긴다. 예측 칸을 먼저 쓰고, 틀려도 괜찮다. 모르면 “모르겠다”라고 쓴다.

h = [9, 4, 7, 1, 8, 2, 6, 3, 5]
heapq.heapify(h)
print(h)               # ①
print(h[0])            # ②
print(h[-1])           # ③
print(h == sorted(h))  # ④
out = []
while h:
    out.append(heapq.heappop(h))
print(out)             # ⑤

값을 읽고 확인하기

h[0]을 읽는 것과 heappop(h)는 하는 일이 같은가?

h[0]은 읽기만 하고, heappop은 루트를 빼고 마지막 값을 올려 아래로 한 경로를 고친다.

표 ③에서 h[-1]은 최댓값이었는가?

h[-1]은 5이고 9는 7번 칸에 있다. 최댓값은 리프 어딘가에 있을 뿐 정해진 칸이 없다.

활동을 마친 뒤 열어 확인한다 · A9 정리: 실제 값과 해설

실제 값: ① [1, 3, 2, 4, 8, 7, 6, 9, 5] ② 1 ③ 5 ④ False ⑤ [1, 2, 3, 4, 5, 6, 7, 8, 9].

  • h[0]은 읽기만 하지만 heappop은 루트를 빼고 마지막 값을 루트로 올린 뒤 아래로 한 경로를 고치므로(A7) 더 많은 일을 한다.
  • 리스트 h는 정렬되어 있지 않다. 그래도 pop할 때마다 가장 작은 값이 루트에 있고 나머지를 다시 힙으로 고치므로, 꺼내는 순서는 정렬된다.
  • h[-1]은 5이고 최댓값 9는 7번 칸(리프)에 있다. 최댓값은 리프 어딘가에 있을 뿐 정해진 칸이 없다. 다른 예로 [7, 2, 9, 4, 11, 5, 8, 3]을 차례로 heappush한 리스트는 [2, 3, 5, 4, 11, 9, 8, 7]이어서 h[-1]은 7, 최댓값은 11이다.
  • B3의 출력은 None [1, 3, 5]이다. heapify는 리스트를 제자리에서 바꾸고 아무것도 돌려주지 않으므로 y는 None이다. h = heapq.heapify(h)처럼 쓰면 h가 None이 되어 이후 h[0]에서 오류가 난다.
  • 용어: 우선순위 큐는 “가장 우선인 것을 꺼내는” 기능이고, 힙은 그 기능을 구현하는 한 가지 방법이다.
  • 최대 힙이 필요할 때의 방법은 3차시 A11에서 직접 확인한다.

일반화 문장 보기

일반화는 여러 사례에 두루 맞는 한 문장이다. “개념 + 개념 + 관계”로 쓰고, 개념어는 숫자나 이름이 아니라 여러 사례에 쓰는 말이다.

8주차 BST 이야기에서 일반화 문장은 어느 쪽일까?

두 번째 문장은 사례 이름 없이 개념어(이진 탐색 트리, 부분 트리)와 이유(~이라서)로 썼다.

내 말로 한 문장 쓰기

오늘 “왜 그런가?”가 궁금했던 활동을 하나 골라, 거기서 본 사실을 “~이므로 ~할 수 있다” 꼴로 쓴다. H1 같은 사례 이름은 쓰지 않는다. 떠오르지 않으면 “쓰지 못함”과 이유를 쓴다.
