활동을 마친 뒤 열어 확인한다 · A11 정리: 결과·원인·해결

그대로 push, pop 4번 한 결과는 [2, 4, 7, 9]이다. heapq의 힙은 최소 힙이라 작은 값부터 나온다.

B1은 [-9, -7, -4, -2]이다. 넣을 때만 부호를 뒤집고 꺼낸 값을 되돌리지 않았다. B2는 4개를 모두 꺼내면 [9, 7, 2, -4]이다. 4만 부호를 뒤집지 않아 4로 들어가 가장 늦게 나오고, 꺼낼 때 -4가 되었다. 첫 값 9만 보면 맞아 보이므로 4개를 모두 확인해야 한다.

해결의 한 예는 넣을 때 값에 −를 붙이고 꺼낸 값에 다시 −를 붙이는 것이다. 부호를 뒤집으면 큰 값이 작은 값이 되어 최소 힙이 먼저 꺼내고, 꺼낸 뒤 되돌리면 원래 값이다. 넣을 때와 꺼낼 때가 짝이어야 하며 한쪽만 적용하면 B1, B2처럼 깨진다.

def push_max(h, x):
    heapq.heappush(h, -x)
def pop_max(h):
    return -heapq.heappop(h)

A12 · K번째 최댓값 설계와 추출3차시 · 11분 · 짝

산출물: 방법별 비용 표, (다) 손 추적표, 동작하는 kth_largest 초안

리스트 nums = [7, 2, 9, 4, 11, 5, 8, 3]에서 K = 3번째로 큰 값을 구한다. 값이 같은 원소는 별개로 센다. 먼저 세 가지 방법을 비교해 보고, 하나를 골라 손으로 추적한 뒤 코드로 추출한다.

학습 내용 · A12 활동 방법과 표 쓰는 법
  1. (가)(나)(다)는 “비교할 후보”이다. 어느 것이 좋은지는 비용 표를 채운 뒤 스스로 판단한다.
  2. (다)를 설계할 때는 힙에 무엇을 두는가, 새 값이 올 때 무엇과 비교해 무엇을 하는가, 답은 힙의 어느 칸에서 읽는가를 정한다. 막히면 스스로 묻는다: 힙에 든 값이 적을 때는 어떻게 하나? 새 값과 비교할 대상은 누구인가?
  3. 비용 표는 정확한 식이 아니어도 된다. N개를 정렬하는 비용은 “N log N 정도”로 쓴다. 힙에 값을 하나 넣거나 빼는 일은 A6·A7에서 센 것처럼 한 경로만 오르내리므로, 그 크기는 힙의 층 수(A4의 높이 표)에 따라 정해진다.
  4. 추적표의 “처리 후 힙 리스트”는 정렬된 리스트가 아니라 A6·A7처럼 자리를 고친 뒤의 힙의 배열이다. 값이 들어오거나 바뀔 때마다 자리를 고친 배열을 쓴다. 한 일 칸에는 “넣는다 / 어떤 값과 바꾼다 / 건너뛴다”를 자기 말로 쓴다.
  5. 코드는 설계를 마친 뒤 실습 코드 2부 A12에서 쓴다. 루트를 빼고 새 값을 넣는 일을 한 번에 해 주는 함수가 있는지는 활동을 마친 뒤 확인 상자에서 확인한다. 막히면 그 쪽의 “골격”을 연다.

세 가지 후보

(가) 정렬

nums를 내림차순으로 sorted한 뒤 K번째 값을 고른다.

(나) 전체 힙

nums 전체를 힙에 넣고, 가장 큰 값부터 K번 꺼낸다.

(다) 힙을 쓰되 보관하는 원소 수를 줄이는 방법

모둠이 직접 설계한다. nums를 한 번씩 훑으며 힙을 쓰되, 힙에 보관하는 원소의 수를 (나)보다 줄이는 방법이다.

(다)의 설계

(다)의 설계를 두세 문장으로 쓴다. 무엇을 힙에 두는가? 새 값이 올 때마다 무엇을 하는가? 마지막에 답은 어떻게 읽어 내는가?

2~3문장으로, 위 세 질문에 순서대로 답한다.

비용 비교

원소가 N개, 구하려는 순서가 K일 때, 각 방법이 “다루는(보관·정렬하는) 원소 수”와 “전체 비용의 식”을 N, K로 쓴다. (모르면 짐작한 대로 쓰고 이유를 적는다.)

쓰는 법: 둘째 칸에는 원소 수를 “N개”나 “2K개”처럼 개수로 쓴다. 셋째 칸에는 N, K를 넣은 식으로 쓴다(꼴: N+K). 정확하지 않아도 되며, 모르면 짐작한 식을 쓰고 넷째 칸에 이유를 쓴다. 넷째 칸은 선택이다.

(다)를 손으로 추적하기 (K = 3)

활동을 마친 뒤 열어 확인한다 · A12 정리: 추적·비용·코드·B4

아래 추적표는 루트 교체를 heapreplace로 한 경우이다. heappop 뒤 heappush로 했다면 4를 처리한 뒤 [4, 9, 7], 11을 처리한 뒤 [7, 9, 11]처럼 배열이 다를 수 있다. 부모가 자식보다 크지 않고(부모 ≤ 자식) 루트가 3번째로 큰 값이면 정답으로 본다.

7넣는다(힙에 든 값이 3개 미만)[7]
2넣는다[2, 7]
9넣는다[2, 7, 9]
4루트 2보다 커서 교체[4, 7, 9]
11루트 4보다 커서 교체[7, 11, 9]

답은 루트 0번 칸의 8이다. 힙 안의 세 값은 상위 3개 {8, 9, 11}이다. 힙에는 지금까지 본 값 중 가장 큰 3개만 남고 그중 가장 작은 값이 루트이므로 루트가 3번째로 큰 값이다. 내보낼 대상이 “3개 중 가장 약한(작은) 원소”이므로 작은 값부터 꺼내는 최소 힙이 맞다. 힙에 든 원소 수는 3개가 될 때까지 늘고 그 뒤로는 3개로 유지된다.

방법보관·정렬하는 원소 수전체 비용(이론값)특징
(가) 정렬NN log N코드가 가장 단순하나 전체를 정렬한다.
(나) 전체 힙, K번 꺼내기N힙 만들기 + K log NK가 작아도 N개를 모두 보관한다.
(다) 크기 K 힙 유지KN log KK개만 보관하고 한 번 훑는다.

N=100만, K=10이면 (가)는 100만×약 20, (다)는 100만×약 3.3 정도이다(손으로 계산한 근사값이며 실행으로 측정하지 않았다).

코드 ①은 heapq.heappush(h, x), ②는 heapq.heapreplace(h, x)이다. heapreplace는 루트를 빼고 x를 넣는 일을 한 번에 한다. heappop 뒤 heappush로도 같은 값을 얻는다. 다만 이 방법은 두 번 자리를 고치므로 힙의 배열 모양은 heapreplace와 다를 수 있다(반환값과 루트의 값은 같다). ②를 h[0] = x로 쓰면 루트 값만 덮어쓰고 자리를 고치지 않아 힙의 약속이 깨진다(A7).

B4는 (루트 2, 힙 크기 8)이다. 교체가 아니라 추가만 해서 힙이 3개로 유지되지 않으므로 루트가 3번째로 큰 값이 아니라 전체의 최솟값이 된다.

기대값은 내림차순으로 정렬한 뒤 k번째 값과 같다. 실패 원인의 예: 같은 값을 하나로 센다, k가 N일 때 처리가 맞지 않는다. k가 N보다 크면 힙이 k개까지 차지 않아 h[0]이 k번째 값이 아니므로 입력 범위(1 ≤ k ≤ N)를 주석으로 밝힌다.

스케줄러: 낮은 숫자 먼저는 [(1, 'alert'), (1, 'deploy'), (2, 'email'), (3, 'lunch')], 높은 숫자 먼저는 [(3, 'lunch'), (2, 'email'), (1, 'alert'), (1, 'deploy')]이다. 높은 숫자 먼저는 우선순위에 −를 붙여 넣고 꺼낼 때 되돌린 결과이다(A11의 방법). 튜플은 앞 원소부터 비교하고 같으면 다음 원소를 비교하므로, 우선순위가 같은 두 작업은 이름 문자열의 사전순으로 alert가 deploy보다 앞선다.

h = []
for t in tasks:
    heapq.heappush(h, t)
print([heapq.heappop(h) for _ in tasks])

h = []
for p, n in tasks:
    heapq.heappush(h, (-p, n))
out = []
while h:
    p, n = heapq.heappop(h)
    out.append((-p, n))                       # 앞의 -p를 되돌려야 원래 우선순위
print(out)

이름 자리에 dict처럼 서로 비교할 수 없는 값을 두고 우선순위가 같으면 TypeError(‘<’ not supported between instances of ‘dict’ and ‘dict’)가 난다. 먼저 들어온 순서를 지키려면 (우선순위, 들어온 번호, 이름)처럼 번호를 둘째 칸에 넣는 방법이 있다.

규모 토론의 기준: 데이터가 100개 정도로 작고 한 번만 구하면 sorted·max가 단순하고 충분하다. N이 매우 크거나 값이 계속 들어오고 그때마다 가장 우선인 것을 꺼내야 하면 힙이 유리하다. 힙은 가장 앞 하나만 보장하고 전체 순서는 보장하지 않는 대신 갱신이 싸다.

세 문장은 모두 거짓이다. ① h = [1, 3, 2, 4, 8, 7, 6, 9, 5]에서 h[-1]은 5이고 최댓값은 9이다. ② 같은 리스트에서 h == sorted(h)는 False이다. ③ B1처럼 꺼낸 값을 되돌리지 않으면 [-9, -7, -4, -2]처럼 음수가 나온다.

다음 주 예고

트리(8주) → 힙(9주) → 그래프(10주). 10주차에는 점과 선으로 이루어진 망형 구조를 다룬다. 그래프에서 “가장 가까운 곳부터 방문하기”가 힙과 어떻게 이어질지 짐작해 본다.
